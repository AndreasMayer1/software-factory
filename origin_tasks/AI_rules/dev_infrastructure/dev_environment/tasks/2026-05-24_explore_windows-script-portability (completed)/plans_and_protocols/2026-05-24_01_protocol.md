# Protocol: Windows-host script portability ACs

## Added to REQ-PROC-054 (stays active)

- **AC-14** — shared project-path resolution mechanism. Precedence: explicit
  arg → co-located config file → in-repo auto-derivation. Config machine-readable
  by both PowerShell and Python. Yields location-independence; own-location-only
  derivation explicitly does not satisfy it.
- **AC-15** — Windows-host install tool: copies all `scripts/windows/` out of
  repo, writes the AC-14 config recording the Mutagen mirror path; target
  configurable, default `<Windows-user-home>/projects/<project-name>/windows-scripts/`.
  Realizes AC-13's "copy out / re-copy on update". Sole sanctioned path to the
  out-of-repo run location.
- **AC-16** — new `scripts/windows/` scripts must use the AC-14 mechanism;
  enforced by `claude-write-script`; holds for `.ps1` and `.py`.
- **Key Decision** + **Common Pitfall** added (location-independence by
  construction; own-location-derivation is a defect once installed out-of-repo).
- **AC-13** reconciled: now references "via the AC-15 install tool".

## Design notes carried for Task D/E (NOT in requirement — impl detail)
- Config file format: JSON (parseable by PowerShell `ConvertFrom-Json` and
  Python `json`). Co-located with installed scripts. Key: project root path
  (the mirror).
- Resolution helper: a dot-sourced `.ps1` for PowerShell scripts + an importable
  Python helper for `smoke_test_llm.py`.
- Install tool: PowerShell, run on Windows host; its own config holds the target
  dir + the mirror path to write into the deployed config.
