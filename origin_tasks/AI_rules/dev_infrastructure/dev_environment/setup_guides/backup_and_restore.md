# Backup and restore

This runbook documents what is backed up, where it lives, how to verify it, and how to restore from each backup source after a failure.

This guide assumes [`wsl_devcontainer_setup.md`](wsl_devcontainer_setup.md) has been completed and the devcontainer is the primary working environment. For the Mutagen sync (which is a separate concern from backup), see [`sync_setup.md`](sync_setup.md).

---

## 1. Backup inventory

| What | Container path | Backup location | Mechanism | Frequency | Survives container rebuild? | Survives WSL reset? |
|---|---|---|---|---|---|---|
| Git repo (all branches, tags, history) | `/workspaces/private_mood_tracker/flutter_app/.git/` | GitHub remote + `~/backup/flutter_app.bundle` (OneDrive) | `git push` to remote; `.githooks/pre-push` writes a full `git bundle --all` and rotates 3 copies | Every push | Yes (WSL ext4) | Yes (GitHub + OneDrive bundle) |
| CCS session state (`~/.ccs`) | `/home/vscode/.ccs/` | `~/ccs-container/ccs-backup-*.tar.gz` (Windows NTFS bind-mount at `%USERPROFILE%\.ccs-container`) | `backup-ccs.sh` via cron; atomic tarball + 3-copy retention | Every 30 min + on container start | Yes (NTFS bind-mount) | Yes (Windows NTFS) |
| Claude Code config (`~/.claude`) | `/home/vscode/.claude/` | Live bind-mount to `%USERPROFILE%\.claude-container` (Windows NTFS) | Docker bind-mount — reads and writes go directly to Windows NTFS | Live (always current) | Yes (NTFS bind-mount) | Yes (Windows NTFS) |
| Parent-level `.devcontainer/` | `/workspaces/private_mood_tracker/.devcontainer/` | `~/backup/_parent_.devcontainer/` (OneDrive) | `.githooks/pre-push` copies with atomic stage-and-swap | Every push | Yes (WSL ext4) | Yes (OneDrive) |
| Parent-level `.vscode/` | `/workspaces/private_mood_tracker/.vscode/` | `~/backup/_parent_.vscode/` (OneDrive) | `.githooks/pre-push` copies with atomic stage-and-swap | Every push | Yes (WSL ext4) | Yes (OneDrive) |
| Windows NTFS mirror (derived) | `/home/vscode/windows_mirror/` | N/A — this IS the backup target for Mutagen | Mutagen one-way-safe sync from WSL ext4 | Near-realtime | Yes (NTFS bind-mount) | Yes (Windows NTFS) |

### What is NOT backed up

| What | Why not | Risk |
|---|---|---|
| Container-installed packages (apt, pip, npm) | Reinstalled by `setup.sh` on every rebuild | None — deterministic from scripts |
| Flutter SDK (`/sdks/flutter/`) | Comes with the `cirruslabs/flutter` base image | None — pulled fresh on rebuild |
| Build artifacts (`build/`, `.dart_tool/`) | Regenerated by `flutter pub get` and builds | None — ephemeral |
| Mutagen daemon state (`~/.mutagen/`) | Recreated by `mutagen project start` from `mutagen.yml` | None — first sync after rebuild is a full reconciliation against the existing NTFS mirror |

## 2. Backup mount paths (devcontainer.json)

The four bind-mounts in `devcontainer.json` that carry backup data:

| Container path | Windows source path | Purpose |
|---|---|---|
| `~/backup` | `%USERPROFILE%\OneDrive\Projekte\Appentwicklung\private_mood_tracker\flutter_app` | Git bundles + parent-config snapshots (OneDrive-synced) |
| `~/windows_mirror` | Local NTFS working copy (not cloud-synced) | Mutagen sync target for Windows builds |
| `~/.claude` | `%USERPROFILE%\.claude-container` | Live Claude Code config |
| `~/.ccs-container` | `%USERPROFILE%\.ccs-container` | CCS tarball snapshots |

### DrvFs ownership after enabling metadata

When `/etc/wsl.conf` has `metadata` enabled (see [`wsl_devcontainer_setup.md`](wsl_devcontainer_setup.md) §3), DrvFs bind-mounts enforce POSIX uid/gid. Existing files default to `uid=1000` (the DrvFs mount default), but the container's `vscode` user is `uid=1001`. All four bind-mount roots need a one-time ownership fix after enabling metadata:

```bash
sudo chown -R vscode:vscode /home/vscode/backup/
sudo chown -R vscode:vscode /home/vscode/windows_mirror/
sudo chown -R vscode:vscode /home/vscode/.claude/
sudo chown -R vscode:vscode /home/vscode/.ccs-container/
```

Without this fix, writes to any bind-mounted folder fail with `Permission denied` — blocking `git push` (bundle backup), Mutagen sync, CCS snapshots, and Claude Code config writes. New files created after the chown inherit `vscode` ownership and do not need further fixes.

## 3. Verification

### Quick healthcheck (run from inside the container)

```bash
# 1. CCS backup freshness (should print OK, < 35 min old)
check-ccs-backup-health.sh

# 2. Git bundle exists and is recent
ls -lh ~/backup/flutter_app.bundle

# 3. Parent-config backup exists
ls ~/backup/_parent_.devcontainer/setup.sh ~/backup/_parent_.vscode/tasks.json

# 4. Claude config bind-mount is live and writable
ls ~/.claude/settings.json
touch ~/.claude/.write_test && rm ~/.claude/.write_test && echo "Claude bind-mount: writable" || echo "Claude bind-mount: NOT WRITABLE"

# 5. Mutagen sync is healthy
mutagen sync list
# Should report: Status: Watching for changes, 0 conflicts, 0 transition problems

# 6. DrvFs bind-mount ownership (all should show vscode vscode)
ls -ld ~/backup/ ~/windows_mirror/ ~/.claude/ ~/.ccs-container/
# If any show "ubuntu ubuntu": run sudo chown -R vscode:vscode <path> to fix
```

### What a healthy state looks like

- `check-ccs-backup-health.sh` prints `OK` with age < 35 min.
- `~/backup/flutter_app.bundle` has a modification time from the last `git push`.
- `~/backup/_parent_.devcontainer/` contains the same files as `/workspaces/private_mood_tracker/.devcontainer/`.
- `~/.claude/` is non-empty, contains `settings.json`, **and** the write test succeeds.
- `mutagen sync list` reports both endpoints `Connected`, `Status: Watching for changes`, zero problems.
- All four bind-mount roots show `vscode vscode` ownership.

> **If ownership shows `ubuntu ubuntu`**: the DrvFs NTFS extended attributes defaulted to `uid=1000`
> (see §2 "DrvFs ownership after enabling metadata"). Run:
> ```bash
> sudo chown -R vscode:vscode ~/backup/ ~/windows_mirror/ ~/.claude/ ~/.ccs-container/
> ```
> Then re-run `check-ccs-backup-health.sh` — it should report OK after a manual `backup-ccs.sh` run.

## 4. Restore scenarios

### 4.1 Container rebuild (routine)

**Trigger**: `Dev Containers: Rebuild Container` from VS Code.

**What is lost**: installed packages, `~/.mutagen/` daemon state, any ephemeral container files not on a bind-mount.

**What is preserved**: everything on WSL ext4 (`/workspaces/private_mood_tracker/`), everything on NTFS bind-mounts (`~/.claude`, `~/.ccs-container`, `~/backup`, `~/windows_mirror`).

**Restore**: fully automatic.

1. `setup.sh` (`postCreateCommand`) runs:
   - Restores `~/.ccs` from the newest `ccs-backup-*.tar.gz` in `~/.ccs-container/` (only if `~/.ccs` is empty after rebuild).
   - Restores `~/.claude` from `~/backup/claude-backup-*.tar.gz` (only if `~/.claude` is empty — normally it's the live bind-mount, so this path is a fallback).
   - Reinstalls all packages (apt, pip, npm, uv, Mutagen, Google Chrome).
2. `postStartCommand` runs:
   - Starts cron (for CCS backup schedule).
   - Runs an immediate CCS backup.
   - Starts the Mutagen daemon and sync session (first sync after rebuild is a full reconciliation — typically fast because most files match).
   - Runs `flutter pub get`.

**Manual verification after rebuild**: run the quick healthcheck from section 3.

### 4.2 WSL reset (`wsl --unregister`, WSL corruption, distro reinstall)

**Trigger**: `wsl --unregister Ubuntu`, WSL2 VM corruption, or intentional distro reinstall.

**What is lost**: the WSL ext4 filesystem — the project source tree at `~/projects/private_mood_tracker/`, all local git branches not yet pushed, all commits not yet pushed or bundled.

**What is preserved**: everything on Windows NTFS — `%USERPROFILE%\.claude-container`, `%USERPROFILE%\.ccs-container`, the OneDrive backup folder, the NTFS mirror.

**Restore steps**:

1. **Reinstall WSL distro** (if needed):
   ```powershell
   wsl --install -d Ubuntu
   ```

2. **Re-clone the project from GitHub** to WSL ext4:
   ```bash
   mkdir -p ~/projects/private_mood_tracker
   cd ~/projects/private_mood_tracker
   git clone <github-remote-url> flutter_app
   ```
   If GitHub is unavailable, restore from the git bundle on OneDrive:
   ```bash
   mkdir -p ~/projects/private_mood_tracker/flutter_app
   cd ~/projects/private_mood_tracker/flutter_app
   git init
   git bundle unbundle "/mnt/c/Users/<user>/OneDrive/.../flutter_app.bundle"
   git checkout develop
   ```

3. **Restore parent-level workspace files** from OneDrive backup:
   ```bash
   cp -r "/mnt/c/Users/<user>/OneDrive/.../private_mood_tracker/flutter_app/_parent_.devcontainer" ~/projects/private_mood_tracker/.devcontainer
   cp -r "/mnt/c/Users/<user>/OneDrive/.../private_mood_tracker/flutter_app/_parent_.vscode" ~/projects/private_mood_tracker/.vscode
   ```

4. **Re-open in VS Code Dev Container**: `Dev Containers: Reopen in Container` from the workspace folder. `setup.sh` and `postStartCommand` handle the rest (CCS restore, package install, Mutagen start).

5. **Verify**: run the quick healthcheck from section 3.

### 4.3 Machine swap (new PC, full rebuild)

**Trigger**: new hardware, fresh Windows install.

**What is available**: GitHub remote, OneDrive (synced to the new machine).

**Restore steps**:

1. **Install prerequisites** per [`wsl_devcontainer_setup.md`](wsl_devcontainer_setup.md): WSL2, Docker Desktop, VS Code + Dev Containers extension.

2. **Configure WSL** (`/etc/wsl.conf`):
   ```ini
   [automount]
   options = "metadata,umask=22,fmask=11"
   ```
   Then `wsl --shutdown` and reopen.

3. **Clone the project** to WSL ext4 (as in 4.2 step 2).

4. **Restore parent-level workspace files** from OneDrive (as in 4.2 step 3).

5. **Create the NTFS mirror folder** for Mutagen:
   ```powershell
   mkdir "C:\Users\<user>\<local-path>\private_mood_tracker\flutter_app"
   ```

6. **Create Claude Code config folders** on Windows:
   ```powershell
   mkdir "$env:USERPROFILE\.claude-container"
   mkdir "$env:USERPROFILE\.ccs-container"
   ```
   If OneDrive has CCS backup tarballs from the old machine, copy them into `.ccs-container\`.

7. **Adjust `devcontainer.json`** mount paths to match the new machine's Windows user and folder structure.

8. **Open in VS Code Dev Container**. `setup.sh` handles bootstrap + package install. `postStartCommand` starts cron, Mutagen, and pulls Flutter dependencies.

9. **Set up GitHub auth** inside the container (for push):
   ```bash
   gh auth login
   ```

10. **Verify**: run the quick healthcheck from section 3. Run `mutagen sync list` to confirm the mirror is populating.

## 5. Recovery from specific failures

### CCS backup is stale (`check-ccs-backup-health.sh` reports STALE)

```bash
# Check if cron is running
sudo service cron status

# If not running, start it
sudo service cron start

# Verify the cron job is installed
cat /etc/cron.d/ccs-backup

# Run a manual backup to confirm the mechanism works
backup-ccs.sh

# If the backup mount is missing
ls /home/vscode/.ccs-container/
# If empty or missing: the Docker bind-mount failed. Restart the container.
```

### Git bundle is missing or outdated

The bundle is only written on `git push` (via `.githooks/pre-push`). If the bundle is stale, it means you haven't pushed recently. To create one manually:

```bash
git bundle create ~/backup/flutter_app.bundle --all
git bundle verify ~/backup/flutter_app.bundle
```

### Parent-config backup is missing

Triggered by `git push`. To create one manually:

```bash
cp -rT /workspaces/private_mood_tracker/.devcontainer ~/backup/_parent_.devcontainer
cp -rT /workspaces/private_mood_tracker/.vscode ~/backup/_parent_.vscode
```

### Mutagen sync is broken

See [`sync_setup.md`](sync_setup.md) section 8 (Healthcheck and recovery) for the full troubleshooting table.

Quick hard reset:

```bash
mutagen sync terminate flutter-app-to-windows
mutagen project start
# Wait for full reconciliation (1-5 minutes)
mutagen sync list
```

## 6. Backup frequency and risk windows

| Backup | Frequency | Risk window (data at risk between backups) |
|---|---|---|
| Git push (repo + bundle + parent-config) | Manual (every push) | All commits since last push. Mitigated by frequent pushes. |
| CCS tarball | Every 30 min (cron) + on container start | Up to 30 min of CCS session state. Low impact — sessions can be re-created. |
| `~/.claude` | Live (bind-mount) | None — always current on Windows NTFS. |
| Mutagen mirror | Near-realtime (continuous sync) | Seconds of lag. Not a backup — it's a derived working copy for Windows builds. |

The largest risk window is **uncommitted or unpushed git work**. The pre-push hook bundles all local branches, so a `git push` is the single action that makes everything durable. The CCS session state and Claude config survive container rebuilds without any user action.
