# ANALYZE — Problem Structure

Ledger: `2026-07-09_001_ideation_ledger.yaml`. Topic class: **composition** (min viable K = 1).

## Scope & goal
Design a mechanism that makes a **deployed** build-mode run (`build.py::run_build_mode`) resumable across
session termination — usage-limit hit, hung/`session_timeout`, or any non-clean child exit — so a run can
be **started by one session, cleanly paused, and resumed by a later cold session**, without ever depositing
an incoherent partial harvest into `test_harness_app/` and without a human threading paths by hand. The
mechanism must unblock TASK-PROC-068-12 and generalize to any long build-mode playground run.

## Core tension (the hazard that shapes everything)
Harvest+discard is **irreversible** and currently **unconditional**. Two failure modes couple:
1. **Partial-harvest incoherence** — deposit half-derived layers into the persistent tree.
2. **Resumable-state destruction** — `rmtree` the copy that held the (already-resumable) ChainState.
Both stem from one root cause: **completion is implicit** ("the child exited") and **state is ephemeral**
(anonymous `mkdtemp`, no handle). Fix completion→explicit and state→durable and both modes close.

## Criteria (full set in ledger `kind:criterion` rows)
Spine: usefulness, feasibility (knockout floor), viability, novelty, risk. Problem-specific band:
`state_durability`, `harvest_coherence_safety` (**KNOCKOUT** — a design that can deposit an incoherent
partial is eliminated), `minimal_new_mechanism`; persona-derived (factory operator, first claim):
`operator_low_supervision`.

## Decomposition (5 sub-problems, contracts in ledger `kind:subproblem` rows)
- **SP-1** durable resume-state location
- **SP-2** run registry & cold re-attach
- **SP-3** explicit completion signal & harvest/discard gating
- **SP-4** usage-limit checkpoint & dual-orchestrator coordination
- **SP-5** generalization to all long build-mode runs

## Sub-problem tensions surfaced
- **SP-1 preserve-vs-rehydrate**: preserving the whole copy is cheap to build but fragile (a `/tmp`
  scratch dir dies on reboot/eviction) and heavy on disk; re-hydrating a distilled bundle survives
  anything durable but must reconstruct a runnable project (re-deploy + re-seed + replay commits) — and
  the copy's ChainState + git commits ARE the distilled bundle already, if they live somewhere durable.
- **SP-3 who owns "done"**: the child's ChainState already knows `complete: true`. The wrapper cannot
  read it after rmtree. The completion signal must cross the copy→host boundary explicitly.
- **SP-4 the nested-orchestrator trap** (developer input 01): pausing the derivation session alone is
  insufficient — the OUTER orchestrator will dispatch the next task, and the INNER orchestrator inside the
  copy is itself a session under the same account window. A usage limit is a *tree-wide* event (shared
  `~/.claude`), which is actually an advantage: the outer orchestrator's existing `rate_limited` path
  already halts new dispatch and resumes `in_progress` — if the deployed run is modeled as an ordinary
  resumable `in_progress` task, the outer pause is *free*.

## Analyze→Ideate adversarial pass (inline)
Attacked the framing for missing sub-problems / un-gathered reuse:
- **ADV-1**: Does re-launching the same contained child re-run `deploy`+`seed`+`snapshot`? If build.py's
  linear steps 1–3 re-run on resume, they would re-overlay and **re-baseline the snapshot**, corrupting
  the net-new harvest diff. → resume must SKIP deploy/seed/snapshot and reuse the preserved baseline.
- **ADV-2**: The inner orchestrator writes its own JSONL under the copy's CCS path; on re-attach, hung
  detection must watch the *resumed* session's JSONL, not a stale one. → run handle must carry the child
  session UUID so re-attach watches the right file.
- **ADV-3**: `harvest_coherence_safety` as knockout may be *too* strict — a run that completed layer N but
  not N+1 has coherent layer-N artifacts. Is per-layer (per-commit) harvest on incomplete ever safe? →
  surfaced as an open design question for the gate (partial-harvest-at-commit-boundary).
These are recorded as gap/consideration rows and folded into synthesis.
