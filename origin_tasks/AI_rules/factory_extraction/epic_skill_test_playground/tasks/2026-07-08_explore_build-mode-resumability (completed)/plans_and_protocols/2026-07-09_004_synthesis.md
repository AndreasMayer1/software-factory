# SYNTHESIZE — Resume Design for the Deployed Build-Mode Run

Ledger: `2026-07-09_001_ideation_ledger.yaml`. Topic class: composition (K=1). 27 divergent ideas across
SP-1..SP-5 × 5 frames. This synthesis composes the surviving ideas into one coherent design and is honest
about what stays uncertain.

## The one-line reframe that unlocks the design
**Model the deployed build-mode run as an ordinary resumable `in_progress` task in the OUTER factory tree,
keyed by a durable run handle, whose irreversible harvest+discard is gated on an explicit completion
signal.** Everything else follows, and most of it is *wiring existing mechanism*, not new machinery.

## Recommended composed design

### SP-1 — Durable resume-state location  (ideas IDEA-01, IDEA-02, IDEA-04-git-fallback)
- `isolated_dir` moves from an anonymous `tempfile.mkdtemp()` in `/tmp` to a **durable runs directory**
  under the factory tree: `.factory/playground/runs/<handle>/copy/`. It survives reboot and `/tmp` eviction.
- The copy is **already per-unit git-committed** by the inner derivation chain (feat_backfill AC-01), so the
  copy *is* the durable checkpoint — no separate state bundle needed for v1.
- On **clean completion** the copy is `rmtree`'d exactly as today. On **pause/incomplete** it is **preserved**.
- Fallback (documented, not v1): `git bundle` the copy to host + re-hydrate a fresh deploy, if disk pressure
  from many preserved copies ever demands it (U4).

### SP-2 — Run registry & cold re-attach  (IDEA-07, IDEA-08, IDEA-09, IDEA-10, IDEA-11-sec)
- **Deterministic run handle** (not anonymous uuid4) a cold session can name.
- Host-side **run registry** `.factory/playground/runs/registry.json`:
  `handle -> {copy_path, child_session_uuid, jsonl_dir, baseline_snapshot_ref, status ∈ {running,paused,complete}}`.
  Least-data (never stores the bound `~/.claude` path), lives under the factory tree, restrictive perms.
- A cold session **discovers** an in-progress run by reading the registry; **re-attach** re-launches the
  contained child (its inner autorun resumes from ChainState) and **SKIPS deploy/seed/snapshot** (ADV-1
  fix — re-running them would re-baseline the net-new harvest diff), reusing the preserved
  `baseline_snapshot_ref`. Hung-detection watches the recorded `child_session_uuid`'s JSONL (ADV-2 fix).
- A **`playground-build-resume` control skill** (mirrors `layer-derivation-resume`) does this with no
  human threading paths by hand.

### SP-3 — Explicit completion signal & harvest/discard gating  (IDEA-12, IDEA-13, IDEA-14, IDEA-16, IDEA-18-audit)
- `run_build_mode` gains an explicit **completion gate**. Harvest+discard runs **only** when
  `COMPLETE = result.succeeded AND result.reason == "exited" AND completion_predicate(copy) is True`.
- Derivation's `completion_predicate` reads the inner **ChainState `complete: true`** (or a `RUN_COMPLETE`
  sentinel the child writes).
- On **INCOMPLETE** (any non-clean reason, or predicate false): **preserve the copy, set registry
  status=paused, and SKIP the harvest entirely** — zero partial deposit into `test_harness_app/`.
- A harvest **manifest** records the completion reason so any deposit (or its absence) is auditable, never silent.

### SP-4 — Usage-limit checkpoint & dual-orchestrator coordination  (IDEA-19, IDEA-20, IDEA-21, IDEA-24; developer input 01)
- **The outer pause is free**: because the deployed run is an outer `in_progress` task, the outer
  orchestrator's existing `classify_session_failure → rate_limited → hold in_progress → resume-after-reset`
  path already halts new-task dispatch and later resumes the deployed run. No new outer pause mechanism.
- **The inner pause is (near) free**: the deployed copy runs the whole factory, hence the same
  `orchestrate.py`; sharing the single `~/.claude` window (AC-12), the inner orchestrator hits the same
  limit and terminates cleanly under its own automated-mode (re-emitting the limit line). Needs
  confirmation (U2).
- New `LaunchResult.reason == "paused"` distinguishes a **planned limit-pause** from `hung`/`session_timeout`.
- On resume, the outer task re-enters `run_build_mode`, which finds the paused run in the registry and re-attaches.

### SP-5 — Generalization to all long build-mode runs  (IDEA-25, IDEA-26, IDEA-27; developer input 01)
- Factor the wrapper around a **BuildRun protocol**: `(durable_state_location, completion_predicate,
  resume_fn)`. Derivation injects `completion_predicate = ChainState-complete`; a generic multi-task
  skill-under-test injects its own done-marker. The registry + `playground-build-resume` skill are shared.
- Recommendation: **design the seam now, implement the derivation path first** (D3).

## Scoring against the gate-approved criteria (viable set — K=1 met)
- **harvest_coherence_safety (KNOCKOUT)** → PASS: preserve+skip-harvest on incomplete = no partial deposit possible.
- **feasibility (KNOCKOUT floor)** → PASS: builds on existing `LaunchResult` fields, ChainState, the
  orchestrator `rate_limited` path, and the resume-skill pattern. Net-new surface is small: a registry
  file, a completion gate, a durable dir, one resume skill, one new `reason`.
- **usefulness** → high (unblocks 068-12; generalizes).  **state_durability** → high.
- **minimal_new_mechanism** → high (mostly wiring + mirroring an existing skill).
- **operator_low_supervision** → high (registry-driven cold re-attach).  **risk** → low–moderate (below).
- **viable_count = 1 composed solution ≥ K=1** — no viable-set collapse.

## Honest uncertainties (still open)
- **U1 (ADV-3)** — per-commit partial harvest: is depositing *coherent whole-unit* layers from an
  incomplete run ever desirable, or is skip-all always right? v1 says skip-all.
- **U2** — is the inner orchestrator's limit-pause truly "free"? The deployed inner autorun's automated-mode
  behaviour inside the jail is **unexercised** (068-18 used a deterministic child that could not hit a limit).
- **U3** — usage-window detection reliability: the marker is scraped from child stdout; a kill mid-write
  yields only a nonzero rc/reason. **Fail-safe**: the gate treats *any* non-clean exit as INCOMPLETE→preserve,
  so detection error degrades to "preserved unnecessarily", never "harvested a partial".
- **U4** — disk cost of preserving whole copies for many concurrent paused runs (git-bundle fallback).
- **U5** — account rotation on resume: a resumed run may land on a different account; the recorded
  `child_session_uuid` JSONL path must still resolve.
