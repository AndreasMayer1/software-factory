## The problem, restated in terms not fully known at task creation
- **State-location**: resumable state need not be re-invented — the isolated copy is *already* per-unit
  git-committed by the inner chain; the fix is to stop putting the copy in ephemeral `/tmp` and to stop
  discarding it unconditionally. Durable location + preserve-by-default.
- **Re-attach**: a cold session re-attaches via a host-side **run registry** (handle → copy_path,
  child_session_uuid, jsonl_dir, baseline_ref, status) and a `playground-build-resume` skill; re-attach
  **skips deploy/seed/snapshot** to avoid re-baselining the harvest diff.
- **Completion signal**: today "done" is implicit (child exited). The design makes it **explicit** —
  `succeeded AND reason=="exited" AND completion_predicate(copy)` — and gates the irreversible harvest+discard on it.
- **Usage-limit checkpoint**: the shared-account, tree-wide limit becomes an *advantage*. Modeling the
  deployed run as an outer `in_progress` task makes the **outer orchestrator pause free** (its existing
  `rate_limited`→resume path). New `LaunchResult.reason=="paused"` names the planned pause.
- **Dual-orchestrator coordination** (developer input 01): the outer pause is free via the in_progress-task
  model; the inner orchestrator shares the window and pauses under its own automated-mode — pending
  confirmation (U2).
- **Generalization** (developer input 01): a **BuildRun protocol** `(state_location, completion_predicate,
  resume_fn)` lets any long playground run reuse the mechanism; derivation is one implementation.

## Two adversarial findings that strengthened the design (synthesize→gate)
- **ADV-synthesize-gate-01**: the "free outer pause" only holds if the run executes *as* an outer task —
  so the mechanism's invocation contract must require the **task-backed path**, not a bare CLI subprocess.
- **ADV-synthesize-gate-02**: a tree-wide limit can kill the wrapper itself mid-launch before it reaches
  the completion gate → **preservation must be the DEFAULT** (durable dir + `registry status=running`
  written *before* launch); discard happens *only* on verified COMPLETE. This is now the core safety invariant.

## Safety invariant (the load-bearing guarantee)
**Preserve-by-default, discard-only-on-verified-complete, skip-harvest-on-incomplete.** Every non-clean
exit — limit, hung, timeout, crash, or wrapper death — degrades to "copy preserved, nothing harvested",
never to "partial deposit". Detection imperfection (U3) can only cause an *unnecessary* preserve.
