# SYNTHESIZE v2 — Resume Design (integrating developer ITERATE feedback)

Iteration 2. Supersedes `2026-07-09_004_synthesis.md` where they differ. Ledger solution **SOL-02**.
Driven by the developer's end-of-run answer (`2026-07-09_06_feedback-checkpoint.md`): the design is
**simpler than v1** — most of it reuses mechanism that already exists, and the explicit "pause" may not be
needed at all.

## What the developer corrected, and what the code confirms
1. **State location was wrong in v1.** Not `.factory/playground/runs/` inside the tree. The playground's
   test-mode **already** uses `workspace.py::create_workspace` → `<parent-of-host>/playground_ws_<uuid8>`,
   a git-init'd sibling of the project (git worktrees / reset need an out-of-project repo root). `build.py`
   simply **diverged to `tempfile.mkdtemp()` (/tmp)** — that is the bug. (G2-1)
2. **The "project-environment config" already exists**: `worktree_root.py` + `worktree.config.json`
   (per-developer, gitignored, precedence explicit → config → parent-of-repo). Reuse it; don't invent a new
   config surface. (G2-2)
3. **Nested orchestrators are real and already self-manage**: `automation/` is deployed into the copy
   (G2-5), so an **inner orchestrator** runs the derivation task-chain; `rate_limit_sleep` shows every
   orchestrator **freezes on all-accounts-limited and resumes after reset** (G2-4). The autorun **stop
   signal** (`stop_requested` in `automation/state.json`, atomic; or SIGINT) is a ready-made pause primitive
   (G2-3).

## The reframe: separate three concerns that v1 fused
v1 fused *completion-gating*, *usage-limit handling*, and *explicit pause* into one "resume mechanism".
They are independent, and only the first is genuinely new work:

| Concern | v1 answer | v2 answer (simpler) |
|---|---|---|
| **A. Completion-gated harvest** (the core safety fix) | gate on ChainState complete | **unchanged — still the load-bearing deliverable** |
| **B. Durable resumable state** | new runs dir + registry | **reuse workspace.py parent-dir + git-init** (already durable & git-backed) + registry |
| **C. Usage-limit handling** | new `reason='paused'`, model run as outer task | **no orchestrator modification** — inner & outer orchestrators already freeze-and-resume |
| **D. Explicit external pause** | build it | **defer (YAGNI)** — no use case found; `stop_requested` documented as the primitive if one appears |

## Full state-space enumeration (the developer's core request)
Outer session ∈ {interactive, autorun} · outer task ∈ {none, present} · inner run ∈ {not-started, running,
complete} · usage-limit ∈ {none, some-accounts, all-accounts} · inner orchestrator ∈ {running, stopped}.

**Start.** An outer session (interactive OR autorun) starts a fresh playground run: build.py creates the
git-backed parent-dir workspace, records the run in the **registry**, and launches the inner run (which
starts the **inner orchestrator** dispatching the derivation chain).

**Waiting for completion.** The outer session must learn when the inner run is done → it **polls an
inner-run-complete signal file** (SP-3, IDEA-30) at a **dynamic interval** (SP-4, IDEA-35) estimated from
remaining ChainState units, not a fixed 15 min.
- **Interactive outer**: the human owns resume; polling is a convenience. Fine.
- **Autorun outer**: the session **must** have a task (the orchestrator only dispatches tasks) — this also
  satisfies ADV-synthesize-gate-01. Two variants:
  - **(a) self-poll [recommended v1-of-this]**: the outer session itself polls the signal file; uniform
    with interactive, keeps the orchestrator single-responsibility. Cost: poll tokens.
  - **(b) orchestrator-monitored**: the session terminates telling the orchestrator "waiting for inner run";
    the orchestrator watches the file and resumes the session on completion. More token-efficient; pushes
    monitoring into the orchestrator (encapsulation cost). Documented as the optimization, not v1.

**Usage-limit (any level).** No new mechanism (C):
- *some accounts*: the hitting orchestrator (inner or outer) rotates account and continues.
- *all accounts*: **both orchestrators freeze** (`rate_limit_sleep`) — inner notices first, outer later (it
  only polls periodically) — and **resume where they left off** after reset. The self-polling outer session,
  if it hits the limit mid-poll, is itself resumed by the outer orchestrator (new account or post-reset) and
  keeps polling. **The shared window makes the whole tree freeze together and thaw together.** (SP-4, IDEA-32)
- **Verified feasibility**: this rests on the inner orchestrator behaving as a faithful copy (it is — G2-5/6)
  and on the inner autorun's automated-mode actually running the chain to completion inside the jail — the
  one thing 068-18 never exercised (U2, still open — a validation task must prove it).

**Completion.** The signal file flips to complete → the outer session (or orchestrator) resumes → build.py's
**completion gate** authorizes `harvest_authored` + workspace teardown (`destroy_workspace`, which already
has an own-prefix safety guard). On any non-complete terminal state build.py **preserves the workspace and
skips harvest** (A, unchanged from v1).

## Is an explicit external pause needed? (direct answer to the developer)
**For the usage-limit case: no.** Orchestrator freeze + completion polling cover it with zero new pause
mechanism. An explicit *preemptive* pause (outer preempts a healthy inner run to do something else) has **no
identified use case** — I could not construct one either: the outer run's only job while the inner run is
in flight is to wait for it. **v2 therefore does NOT build an explicit pause.** If a real preempt case ever
appears, the mechanism is already there: write `stop_requested` to the inner copy's `automation/state.json`
(or SIGINT the inner orchestrator) to pause; start the inner orchestrator again to resume (G2-3). This is
recorded as the documented extension point, not v1 scope.

## The genuinely-new work (small)
1. **Completion signal + gated harvest** in build.py: launch → poll inner-run-complete → only on complete do
   `harvest_authored` + teardown; else preserve + skip harvest. (The v1 core, intact.)
2. **build.py adopts `workspace.py` / `worktree_root.py`** (parent-dir, git-init, config) instead of
   `mkdtemp()`. Largely deleting `mkdtemp` and calling the existing helpers.
3. **Run registry** recording run state (workspace path, inner session/orch handle, status) so a cold
   session re-attaches and so the "session must have a task" constraint relaxes to a safety net (SP-2, IDEA-37).
4. **Dynamic poll helper** (remaining-units → interval).
5. **A validation task** proving the inner autorun actually runs a real chain to completion under a real
   usage-limit inside the jail (closes U2 — the thing 068-18 could not exercise).
NOT built: `reason='paused'`, an explicit pause API, orchestrator modifications.
