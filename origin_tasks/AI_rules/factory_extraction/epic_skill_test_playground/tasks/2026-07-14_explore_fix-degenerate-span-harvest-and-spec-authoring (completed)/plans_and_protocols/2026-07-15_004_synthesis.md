# SYNTHESIZE — Composed Design (degenerate-span harvest fix)

**Topic class:** composition · **K = 1** · **viable_count = 1** (one coherent composed design survives all
weighted criteria; no knockout criteria) → no recovery needed. Authored inline after the synthesize agent
was terminated by a weekly usage limit; composed from the 38 divergent idea rows + the 7 analyze→ideate
adversarial gaps in the ledger.

## The crux (restated)
Split the two meanings the mechanism currently collapses into `ESCALATED`:
**"nothing to author here"** (a mandatory zero-authoring-pair span — vacuously complete) vs
**"something to author, not done"** (a real blocker / silent under-finish). The design gives each its own
*true* completion signal.

---

## Recommended design — per sub-problem

### SP-1 — Fix locus: a distinct `VACUOUS` unit disposition, granted only on structural proof
Add a terminal `UnitStatus.VACUOUS` (name provisional — could be `NO_OP`/`DEGENERATE`; the stable choice
is "a third terminal distinct from DONE and ESCALATED"). The harvest oracle treats **`DONE ∪ VACUOUS`** as
"derivation finished" (idea: *software_architect/association*, *manufacturing/jidoka-split*,
*biology/vacuous-truth*).

**The load-bearing rule that preserves the ADV-01 poka-yoke:** `VACUOUS` is granted **only** by a
**mechanism-computed structural zero-authoring-pair proof** (from `resolve_spans` — the span genuinely has
no internal layer to author), **never** by a child session self-declaring completion. The content-gate
poka-yoke (`_resolve_gate_outcome`: a DONE without a passing gate → ESCALATED) is **untouched** and still
governs every span that *has* authoring pairs. So `VACUOUS` cannot mask a real under-finish: it exists only
where there is provably nothing to gate. This is exactly the *feasibility-spectrum* framing "empty-gate
outcome = PASS-VACUOUS **gated on structural zero-pair proof**, real gates stay fail-closed".

**Rejected alternatives (with reason):**
- *Overload `DONE`* — lies (DONE asserts authored+gated content), and would require bypassing the poka-yoke.
- *Oracle-only tolerance* (make the strict all-DONE oracle count an empty-gate ESCALATED as satisfied) —
  `ESCALATED` is overloaded (real `gate_content_fail` blockers share it), so the oracle cannot reliably tell
  a degenerate no-op from a real gate failure without the disposition split. Fragile at the HIGH-EGP-F seam.
- *Upstream "no unit for a zero-pair span"* (relax `plan_chain` arity) — collides with the span-indexed
  chain-state and `len(span_units)==len(spans)`, and breaks the oracle's "no units → False" guard for an
  all-degenerate chain (ADV-05). Kept only as a possible **future** staged step (*sw_arch/feasibility*:
  "enum now, predictor next, morphism-typed spans later"), not the primary fix.

**Stamp locus:** stamp the expected `VACUOUS` disposition at unit creation in `plan_chain` from the resolved
span's zero-pair structure (*manufacturing/defect-at-source poka-yoke jig*); `complete_unit` honors the
stamp instead of forcing `ESCALATED('gate_content_fail')` on an empty gate. (plan-time stamp is preferred
over decide-at-completion because it makes SP-3's pre-flight prediction exact — impl detail, see residual.)

**Generality (ADV-04/05):** `VACUOUS` applies to *any* structurally zero-authoring-pair span regardless of
direction (FORWARD / REVERSE / BIDIRECTIONAL) and to the `task_code`-excluded boundary, and to multiple
degenerate spans anywhere in a chain.

### SP-2 — AC-18/AC-19 clarification
- **AC-18** gains `VACUOUS` in its outcome vocabulary and its "abandoned" definition is narrowed to name
  **real authoring**: *abandoned* = clean child exit + oracle not-finished + no recorded blocker/escalation
  **and at least one unit that has real authoring pairs is left not-terminal**. A chain whose only
  non-`DONE` units are structurally-degenerate (`VACUOUS`) spans is **complete** (oracle satisfied by
  `DONE ∪ VACUOUS`), never *abandoned* and never blamed on the skill-under-test. This keeps the real
  guarantee true — "abandoned = the skill-under-test silently under-finished **real** authoring" — while
  excluding "the chain had a mandatory no-op span". The external referent extends to include the **per-unit
  structural degeneracy** observed in the real run vs the playground classification (still EGP-F, HIGH).
- **AC-19** substance unchanged (no oracle → cannot certify complete; an in-flight background agent at `-p`
  return → not a clean complete exit). Clarify only that "the derivation finished" = every real-authoring
  span `DONE` **and** every structurally-degenerate span `VACUOUS`.

### SP-3 — Harvestability pre-flight: an offline oracle predictor, resume-stamped
A **plan-time, zero-cost** predictor that reuses `resolve_spans` + the per-span disposition typing + the
injected oracle's predicate to answer "can this spec **ever** harvest?" **before any deploy is spent**
(*ops/hydrotest*, *ops/leak-detector*, *manufacturing/zero-harvest-margin*, *qa/property-test*).
**Contract:**
- **Input:** the spec (`fixed_layers`, `span_units`) + the acceptance oracle to be injected.
- **Computes:** `resolve_spans` → per-span expected disposition (`VACUOUS` for a zero-pair span, else
  "needs authoring") → predicted oracle verdict over the **best-case terminal state** (all real spans
  `DONE`, all degenerate spans `VACUOUS`). If even the best case cannot satisfy the oracle, **fail loudly at
  plan time with a distinct "doomed-spec" exit code** — never reach a deployed run.
- **Placement:** in the mechanism layer as a shared planner↔oracle module, invoked by
  `layer-derivation-start`; the result is persisted as a re-validated **`harvestable` stamp** re-checked on
  **both `-start` and every resume** (ADV-sg-06 / *ops/feasibility*: the stamp is what stops resume from
  skipping the gate).
- **Simulation depth:** only deterministic structure (span resolution + disposition typing + oracle
  predicate over the predicted terminal) — it authors nothing.

### SP-4 — Spec-authoring surface: derive-not-author + teaching linter == the pre-flight gate
**Do not add a standalone skill.** Extend `layer-derivation-start` with a guided step that **emits the spec
from anchor + `fixed_layers`**, deriving `span_units` structurally and stamping degenerate spans — so a
malformed/degenerate-span mapping is **structurally inexpressible** (*persona/inversion*: "author supplies
only `fixed_layers`; tooling derives `span_units`"; *manufacturing*: "mistake-proof the format";
*persona/analogy*: "greyed-out read-only fields"). Back it with a **governed spec template/contract in the
skill/mechanism layer (NOT `doc/`)** documenting the span↔unit model + degenerate-span rule, and a **spec
linter whose teaching error messages ARE the pre-flight gate** (*persona/feasibility*) — so author-time
guidance and plan-time enforcement are the **same code** and can never drift (author-time and gate agree by
construction). Teaching is primarily by structural derivation + a **derivation trace** that shows the author
which span drove the classification (*persona/random_stimulus*), not by prose.

### Migration + reporting tier (its own wave — ADV-02/03/06)
- **Reporting:** `layer-derivation-status` reports `VACUOUS` as **"no-op complete"**, not the phantom
  "awaiting answer → pending_feedback" it currently shows for an empty-gate `ESCALATED`.
- **State migration:** pre-existing persisted `ESCALATED('gate_content_fail')` units on structurally
  zero-pair spans are re-interpreted / migrated to `VACUOUS` (decision: re-interpret-at-load vs one-shot
  script — residual). The 068-26/068-12 **Option-A workaround becomes retire-able** — those span-0 units
  would be `VACUOUS` automatically.
- **Tests:** migrate the ≥7 `ESCALATED`-skip assertion sites via **one shared test helper, TDD-first**
  (*qa/scamper*).

## How the four decisions cohere (composition check)
The `VACUOUS` disposition (SP-1) is the single label that: SP-2 names in AC-18/19, SP-3 predicts at plan
time, and SP-4 teaches/derives. The pre-flight (SP-3) and the authoring linter (SP-4) are the **same
predicate** run at two times (author-time and plan-admission), so guidance and gate cannot disagree. The
real-under-finish guarantee (C1) is preserved because `VACUOUS` is a mechanism-proved structural fact, not a
child claim, leaving the poka-yoke fully in force for every authoring span.

## Residual uncertainty (honest)
1. **All-degenerate chain**: is a chain with *only* `VACUOUS` spans "complete-but-empty-harvest" or a
   mis-specified spec the pre-flight should REJECT? Leaning: pre-flight **warns/fails** an all-degenerate
   spec (nothing to author usually means a wrong `fixed_layers` set), distinct from a mixed chain. **Needs a
   decision** — affects an AC.
2. **Stamp locus**: `plan_chain`-at-creation vs `complete_unit`-at-completion (both viable; plan-time
   preferred for pre-flight exactness). Impl detail, not an AC.
3. **Oracle awareness**: make the oracle generically `VACUOUS`-aware vs treat `VACUOUS` as a DONE-equivalent
   terminal the existing all-DONE predicate accepts. Mechanism detail.
4. **Migration mechanism**: re-interpret-at-load vs one-shot migration script for persisted `ESCALATED`
   units. Impl detail.
5. **`screen_derivability` (ADV-07)**: it is dead code in the production path. Should the fix wire
   empty-required-elements handling into the same `VACUOUS`/degenerate route, or leave it? **Scope decision**
   — affects blast radius.
