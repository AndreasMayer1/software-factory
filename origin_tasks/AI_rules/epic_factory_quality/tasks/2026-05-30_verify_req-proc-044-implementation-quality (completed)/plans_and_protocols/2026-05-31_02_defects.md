## DEFECT-3 — goal_metadata.yaml target_package pattern matches zero real values (AC-05, HIGH)

**Location:** `.claude/schemas/goal_metadata.yaml` L147–151.
**Current:** `pattern: "PKG-[0-9]+\\.[0-9]+\\.[0-9]+-[a-z]+"`, example `PKG-0.0.1-core`.
**Reality:** all real values are plain package names — "Transfer Data Model"(55),
"Adaptive Scanner Settings"(13), "claude-optimize"(10), "Therapist Plan Management"(5),
"QR Transfer Send"(4), … (package names come from RELEASE_BACKLOG.md, not a PKG-x.y.z code).
**Repro:** `grep -rh '^target_package:' requirements_tasks --include=goal.md | sort | uniq -c | sort -rn | head`
**Fix:** remove the bogus pattern (package names are free-form, sourced from
RELEASE_BACKLOG.md) or replace with a pattern/enum that reflects real backlog names.
Currently harmless at runtime (validator ignores `pattern`) but actively misleading as
documentation — the `requirements_frontmatter.yaml` `target_package` field already
documents this correctly (free-form, names from RELEASE_BACKLOG.md); align the goal schema to it.

## DEFECT-4 — real-corpus schema smoke test silently skips (AC-04/test robustness, MEDIUM)

**Location:** `scripts/tests/test_validate_against_schema.py::test_real_goal_md_against_real_schema` (L87–99).
**Symptom:** hardcoded path
`.../2026-05-29_impl_skill-contracts-wave-2-consumers/goal.md` no longer exists (folder
renamed/moved), so the test hits `pytest.skip` and provides zero protection. This is the
only test exercising the schema against the real corpus — i.e. the test that should have
caught DEFECT-1/2/3 is disabled by path brittleness.
**Fix (must use `claude-write-script` skill — file under scripts/):** replace the single
hardcoded path with iteration over a representative real corpus sample (or all goal.md /
requirements.md), asserting zero validation errors. This converts AC-05 from "audited
once" to "continuously guarded". After DEFECT-1/2 are fixed this test should pass green
across the corpus; until then it documents the expected-clean target.
