# Plan: Implement Interactive Feedback Checkpoint Capture

Date: 2026-06-02
Task: TASK-PROC-044-03-01
Type: impl (non-code deliverables: a Python writer script + skill/contract edits)

## Objective

Capture developer-steered decisions in interactive skill sessions as `feedback-checkpoint`
files in the affected task's `plans_and_protocols/`, completing the artifact class whose
automated-mode twin already exists (REQ-PROC-041-04, `orchestrate.py::_archive_feedback_checkpoint`).

## Key design decisions (with developer steering — captured per this feature's own intent)

- **Insertion point = `task-complete`, main session.** Universal task close-out; runs while the
  full session is in context. Context compression is OFF in the factory (developer correction),
  so all steering decisions from the short session are intact at close — no at-gate wiring needed.
  Capture MUST run in the orchestrator's main session, not a fresh sub-agent (a fresh agent never
  saw the steering).
- **No user-approval gate** (developer steering, 2026-06-02). The orchestrator reviews the session
  for steered decisions and writes the file(s) automatically. Zero friction; the developer already
  spoke. Plain "approved as-is" → no file.
- **Filename drops TASK-ID** (developer steering, 2026-06-02): `YYYY-MM-DD_feedback-checkpoint.md`
  (+ `_NN` suffix when multiple steered decisions occur in one task). The file lives inside the
  task's own `plans_and_protocols/`, so location already identifies the task. `orchestrate.py`'s
  `_..._<TASK-ID>.md` convention exists because the automated archival runs from OUTSIDE the task
  folder (processing `pending_feedback/<TASK-ID>/`); the interactive writer does not need it.
- **Decoupled writer.** A new standalone script implements the AC-06 envelope independently — it
  does NOT import or mirror `orchestrate.py`. Format conformance (AC-02) is pinned by a unit test.

## Envelope (AC-02 → REQ-PROC-041-04 AC-06, mode: interactive)

```
---
skill: <skill that hit the gate>
mode: interactive
decision: <revised | rejected | redirected>
task_id: <TASK-ID>          # envelope field, NOT in filename
captured_at: YYYY-MM-DD
---

# Question
<what the skill/agent proposed>

# Developer Answer
<developer's steering words, verbatim>

# Rationale Captured
<the "why" the produced artifact does not itself record>
```

## Deliverables

1. `scripts/tasks/write_feedback_checkpoint.py` — standalone writer (stdlib only, tier-B), CLI:
   takes skill, decision, task_id, protocols-dir, and verbatim text (via file to avoid shell
   mangling); emits the leaner-named file with the AC-06 envelope. Idempotent `_NN` suffixing.
2. Unit test pinning the envelope/body format (AC-02) + filename glob (AC-03) + no-TASK-ID filename.
3. `task-complete/SKILL.md` — new main-session step (interactive mode only; skip when
   `CLAUDE_AUTOMATED_MODE=1`): review session for steered decisions, write one checkpoint each via
   the script. No `AskUserQuestion`.
4. `task-complete/contract.yaml` — document the side-effect + `may_invoke`.
