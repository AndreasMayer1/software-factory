## Context

REQ-PROC-061 AC-11 requires the monthly review to classify each direct pubspec.yaml
dependency before version-bump evaluation:
- (a) directly imported: ≥1 `import 'package:<name>/` in lib/, test/, integration_test/
- (b) indirectly required: platform binaries, code-gen tools, or runtime support library
  for another direct dep; chain must be named
- (c) no evidence of use → removal candidate, NOT upgrade candidate

The monthly review is currently driven by the `monthly-dep-review` cron routine (ID:
`trig_01B9kRzpFAbiFSTvfN4K2Dng`), which reads `doc/process/dependency_lifecycle.md`
as its policy reference. A future migration (TASK-PROC-061-10) will move the review
to a local standing task (blocked on TASK-PROC-065-04-01 date-gate primitive).
Both mechanisms will use the same script.

## Deliverables

### 1. `scripts/release/check_dependency_usage.py`

**Purpose**: classify all direct pubspec.yaml dependencies by usage evidence.

**Algorithm**:
1. Parse `pubspec.yaml` with PyYAML; collect `dependencies:` + `dev_dependencies:` names,
   excluding SDK packages (spec has `sdk:` key).
2. Scan all `*.dart` files in `lib/`, `test/`, `integration_test/` for:
   `import ['"]package:<name>/` (single or double quotes)
3. Count matches per package.
4. Classify:
   - import_count > 0 → directly_imported
   - in INDIRECT_REQUIREMENTS dict → indirectly_required (with reason string)
   - else → no_evidence_of_use
5. Output:
   - Human-readable table (default)
   - JSON (--json flag, for automation consumption)

**INDIRECT_REQUIREMENTS dict** (documented chains):
- `sqlite3_flutter_libs` → platform binaries for drift NativeDatabase (desktop + Android)
- `path` → runtime path utilities used by drift for database file-path resolution
- `build_runner` → code-gen runner for drift_dev, freezed, injectable_generator, json_serializable
- `drift_dev` → code-gen companion for drift (generates .g.dart schema files)
- `freezed` → code-gen companion for freezed_annotation (generates .freezed.dart)
- `injectable_generator` → code-gen companion for injectable (generates get_it registration)
- `json_serializable` → code-gen companion for json_annotation (generates .g.dart JSON serialization)

**SDK packages excluded** (not pub packages, always required):
- flutter, flutter_test, flutter_localizations, integration_test

**Exit code**: always 0 (reporting tool, not a gate)
