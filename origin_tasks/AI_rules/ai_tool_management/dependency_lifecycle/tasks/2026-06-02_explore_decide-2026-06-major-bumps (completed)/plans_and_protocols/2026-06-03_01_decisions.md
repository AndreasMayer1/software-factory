## Per-Package Decisions

### 1. `get_it` 8.2.0 → 9.2.1 — **Go**

**Breaking changes reviewed:**
- v9.0.0: `strictDisposalOrder` parameter removed from `reset()`, `resetScope()`, `popScope()`, `popScopesTill()`, `dropScope()`. Disposal order is now always strict LIFO by registration sequence number.
- v9.2.0: `allReady()` caches its Future and returns the same instance on repeated calls (cache invalidated on new async singleton registration). Behavioral change, same API.

**Call sites assessed:**
- `lib/core/injection/injection_container.dart`: uses `GetIt.instance`, `getIt.allReady()`, `getIt.registerSingleton<T>()`, `allowReassignment = true`. None of these are affected.
- `lib/config/routes/app_router.dart`: uses `GetIt.I<T>()` and `GetIt.instance<T>()`. Unaffected.
- Grep for `strictDisposalOrder` across `lib/` and `test/`: **zero hits**. Breaking change does not apply.

**Condition that would change decision:** If `strictDisposalOrder` were used, each call site would need the argument removed. Confirmed absent.

**Bundled with:** `injectable` + `injectable_generator` (must move in lockstep). See TASK-PROC-061-14.

### 2. `injectable` 2.5.1 → 3.0.0 — **Go**

**Breaking changes reviewed:**
- `includeMicroPackages` option removed from `@InjectableInit`. External package modules must now be listed explicitly via `externalPackageModulesBefore`/`externalPackageModulesAfter`.
- `usesNullSafety` option removed from `@InjectableInit`. Null safety is always assumed.
- `injectable` 2.6.0 updated its `get_it` constraint to `"7.2.0 < 10.0.0"`, meaning it is compatible with get_it 9.x.

**Call sites assessed:**
- `lib/core/injection/injection_container.dart:18–22`: `@InjectableInit(initializerName: r'$initGetIt', preferRelativeImports: true, asExtension: false)` — no `includeMicroPackages` or `usesNullSafety` arguments present.
- Annotations used: `@injectable`, `@singleton`, `@lazySingleton`, `@module`, `@Named`, `@Environment` — all unchanged.
- `$initGetIt()` call signature: unchanged.
- Generated file `injection_container.config.dart`: will need re-generation via `build_runner` (same as any annotation change). No structural format change documented.

**Condition that would change decision:** If `includeMicroPackages: true` were used in `@InjectableInit` for external package DI modules, those modules would need explicit listing. Confirmed absent.

### 4. `go_router` 16.2.4 → 17.2.3 — **Go**

**Breaking changes reviewed:**
- v17.0.0: Shell route observer notification behavior changed. `ShellRoute` navigation events now notify `GoRouter`'s root observers by default (previously they did not). A `notifyRootObserver` parameter was added to `StatefulShellRoute`, `ShellRoute`, and related classes to opt out.

**Call sites assessed:**
- `lib/config/routes/app_router.dart`: `GoRouter(...)` has no `observers:` parameter — no NavigatorObservers are registered. The behavioral change has no impact since there are no observers to be notified.
- `StatefulShellRoute.indexedStack(...)` used; no `notifyRootObserver` override needed since there are no observers.
- `state.matchedLocation`, `state.extra`, redirect callback signature, `GoRouterRefreshStream`, `GoRoute`, `StatefulShellBranch`, `RouteBase`: all unchanged per changelog.

**Condition that would change decision:** If `NavigatorObserver`s were registered on the router, the new default notification behavior could cause duplicate analytics/state events. Grep for `NavigatorObserver` and `observers:` in `lib/`: zero hits. Not applicable.

### 5. `camera` 0.11.4 → 0.12.0+1 — **Go**

**Breaking changes reviewed:**
- `camera` package itself: no breaking changes to `CameraController`, `CameraDescription`, `ResolutionPreset`, or `ImageFormat` between 0.11.x and 0.12.x. v0.12.0 adds video stabilization (additive); v0.12.0+1 makes `Optional.of` constructor `const` (additive).
- `camera_platform_interface` (affects local fork `camera_windows_patched`): multiple new abstract methods added between current and target versions:
  - v2.7.0: `setImageFileFormat()` added
  - v2.9.0: streaming support query method added
  - v2.10.0: `CameraLensType` enum introduced
  - v2.11.0: `VideoCaptureOptions.enablePersistentRecording` added
  - v2.12.0: video stabilization support added
  - v2.13.0: `setJpegImageQuality()` added

**Call sites assessed:**
- `lib/features/therapist/data_receive/presentation/screens/therapist_receive_screen.dart`: imports `package:camera/camera.dart hide ImageFormat` and `package:camera_windows/camera_windows.dart`
- `lib/features/therapist/data_transfer/data/services/i_camera_adapter.dart`: imports `CameraController`, `CameraDescription`, `ResolutionPreset` — no breaking changes to these
- `lib/features/client/data_receive/presentation/screens/data_beam_scanner_screen.dart`: imports `package:camera/camera.dart hide ImageFormat`
- `packages/camera_windows_patched/`: the local fork implements `camera_platform_interface`. New abstract methods in the interface will fail compilation unless implemented or stubbed in the fork.

**Assessment:** The camera package bump itself is safe. The fork needs stub implementations for new abstract interface methods. Effort is Medium — the impl task must:
1. Check which `camera_platform_interface` version `camera 0.12.x` pulls in
2. Identify which new methods are abstract (vs. have default implementations)
3. Add stub implementations in `camera_windows_patched/` for each required method

**Condition that would change decision to Skip:** If the fork's `CaptureAndDecodeFrame()` platform channel uses an internal API that was removed in `camera_platform_interface`. The call sites show no such dependency; the patched entry point is additive to the interface.

### 8. `bloc_lint` 0.3.7 → 0.4.1 *(dev)* — **Defer**

**Breaking changes reviewed:**
- No lint-rule breaking changes. The only change in 0.4.x is bumping the analyzer frontend dependency to `_fe_analyzer_shared >=93.0.0 <=99.0.0`.

**Pin status re-evaluated:**
- `bloc_lint` 0.4.x requires `_fe_analyzer_shared >=93.0.0`
- `clean_architecture_kit` 2.0.1 (latest as of 2026-06-03) requires `analyzer ^8.0.0`, which caps `_fe_analyzer_shared` at ~91.x
- These constraints are **mutually exclusive** — confirmed no new release of `clean_architecture_kit` that lifts the analyzer ceiling
- The existing pin `bloc_lint: ^0.3.7` with the documented pubspec comment is correct and must stay

**Decision: Defer.** The pin is the correct workaround. No upgrade is possible without a `clean_architecture_kit` release that upgrades to `analyzer ^9.x`. The existing TASK-PROC-061-12 (`2026-06-03_explore_reevaluate-analyzer-ceiling`) already tracks the analyzer-ceiling re-evaluation — that task is the natural trigger for revisiting this bump.

**Condition that would change decision to Go:** `clean_architecture_kit` publishes a version with `analyzer ^9.x` or later, resolving the `_fe_analyzer_shared` conflict. Monitor via TASK-PROC-061-12.
