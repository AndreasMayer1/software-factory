# Goal: Explore — Scribble Web Viewer: Effort Estimation

## Objective

Estimate the effort required to build a local web viewer (with a minimal server) for browsing the HTML scribble screens generated by the `ui-create-scribble` skill. The outcome is a concrete build-vs-skip recommendation so the user can decide whether to invest.

## Context

The `ui-create-scribble` skill generates multiple HTML files per screen (one file per screen, one `index.html` per version). Currently:

1. **Ergonomics**: Files must be opened individually from the filesystem — cumbersome for multi-screen flows.
2. **Cross-Origin errors**: The component library (`_scribble_components/components.js`) is loaded via relative path. Opening HTML files directly in a browser triggers CORS blocking, so components do not render — a hard blocker.
3. **AC-18 baseline**: `scripts/generate_flow_scribble_index.py` already exists and generates a per-flow `scribble_index.html` (iframe-based). It has not yet been run in practice and likely shares the same CORS problem.

## Exploration Questions

1. **CORS diagnosis**: Does opening a current scribble HTML directly in Chrome/Edge block `components.js`? Reproduce the error, document the exact failure mode.
2. **AC-18 status**: Is `generate_flow_scribble_index.py` functional? Does its iframe approach resolve or inherit the CORS issue?
3. **Minimal server options**: What is the simplest server approach that unblocks CORS with near-zero setup?
   - Python `http.server` one-liner (already available in the devcontainer)
   - Node `serve` / `http-server`
   - A small custom Flask/FastAPI server
   - Embedded in a Claude skill (auto-start on demand)
4. **Feature scope vs. effort**:
   - **Option A (Minimal)**: Fix the CORS issue only — document a one-liner to start a server; let users open files as before. Estimate: hours.
   - **Option B (Flow index)**: Make `generate_flow_scribble_index.py` work end-to-end (fix CORS, integrate with skill Phase 5a). Estimate: hours.
   - **Option C (Global viewer)**: Build a server + single-page HTML overview listing all requirement folders that have scribbles, grouping by feature + iteration, with click-through navigation between screens in the correct flow order. Estimate: days.
5. **Existing infrastructure reuse**: Can the Python script + the devcontainer's built-in `python3 -m http.server` cover most of Options A and B at essentially zero marginal cost?

## Scope

### In Scope
- Reproducing and documenting the CORS error
- Reviewing `generate_flow_scribble_index.py` code and AC-18 requirement text
- Estimating effort for Options A, B, and C (hours/days, not story points)
- Proposing a concrete recommendation (which option, if any, to implement)
- Identifying which new/updated ACs would be needed for the chosen option

### Out of Scope
- Actual implementation of any option
- Changes to the `ui-create-scribble` skill
- UI polish or production-readiness
