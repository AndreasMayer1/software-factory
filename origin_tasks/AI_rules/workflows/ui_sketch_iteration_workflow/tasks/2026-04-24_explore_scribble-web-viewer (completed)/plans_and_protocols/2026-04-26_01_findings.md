## 1. CORS Diagnosis

**Result**: CORS will block `components.js` when scribble HTML files are opened directly from the filesystem.

**Root cause**: `components.js` uses `fetch()` to load component templates (e.g., `/_scribble_components/c_navigation_bar/template.html`). Browsers block `fetch()` on `file://` URLs by same-origin policy — Chrome and Edge have enforced this since ~2018.

**Reproduce steps** (once any scribble exists):
1. Open any `requirements_tasks/.../scribbles/vN/01_screen.html` directly in Chrome/Edge via File > Open
2. Open DevTools → Console
3. Expected: `Access to fetch at 'file:///workspaces/.../requirements_tasks/_scribble_components/...' from origin 'null' has been blocked by CORS policy`
4. Visual result: `data-component` divs fall back to grey `[Component: c_xxx]` placeholder text (graceful degradation — layout is visible but components missing)

**Iframe CORS (AC-18 scribble_index.html)**: `generate_flow_scribble_index.py` builds iframe `src` using absolute paths (`/requirements_tasks/...`) — these also fail on `file://` for the same reason.

**Note**: No scribbles have been created in practice yet — the system is defined but never exercised.
