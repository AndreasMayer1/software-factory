### Step 1.5 (NEW) — Per-flow walk validation
- Guard: only if `flow_positions` is present in metadata.yaml.
- Group `flow_positions` entries by `flow_id`; sort each group by `step_number`.
- For each participating flow, read `requirements_user_needs/user_flows/<flow_id>/flow.md` and extract
  the step intent (description/system-response) for each step_number present in `flow_positions`.
- For each (step, screen_file) pair: read the screen HTML; verify the screen's elements support the
  step's intent.
- Classify each unsupported step:
  - **Scribble gap**: flow step is valid but screen is missing/wrong → add to gap list for step 2.
  - **Flow flaw**: the flow step is structurally missing from flow.md, contradicts a sibling step,
    or references data the flow never introduces → create a revision task via the `task-create`
    revision sub-procedure (`reason: flow_flaw`, `target_skill: ux-create-flow`,
    `responder_required: human`, `blocks_completion_of: <this-task-ID>`).
    Do NOT include in the scribble gap list.
- Collect walk sequence per flow: `{flow_id: [screen_file1, screen_file2, ...]}` for step 4.5.

### Step 2 — Merge (existing, addendum)
Include scribble-level gaps from step 1.5 in the merged gap set.

### Step 4.5 — Auto-review brief (existing, addendum)
