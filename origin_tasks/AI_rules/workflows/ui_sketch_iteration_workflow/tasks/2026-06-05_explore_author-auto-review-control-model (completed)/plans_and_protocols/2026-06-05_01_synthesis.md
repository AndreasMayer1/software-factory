### Decision 1 — Sequential reviewer execution (R2§2 §2.ii)

Each reviewer agent in `ui-scribble-auto-review` runs to completion before the next starts.
No parallel fan-out. Rationale: if the session/token limit is hit mid-run, only the in-flight
agent is left incomplete; parallel would require ALL agents to restart.

**Note from R2§2**: this interacts with CLAUDE.md cache rule — sequential reviewers extend
wall-clock time, so background execution + heartbeat discipline matters more, not less.

### Decision 2 — Gate-on-convergence default (R2§2 §2, PROP-13A)

Default cadence = `auto-to:[converged]`: human gate fires only when auto-review has converged
(no `severity ≥ MEDIUM` finding in the latest round). The other named policies (`every`,
`after:[N]`, `gate-at-v1`) are optional overrides, not required.

Developer flagged mild uncertainty about whether the question was fully understood — treat
"converged-default" as the confirmed design intent (R2§2 final sentence).

### Decision 3 — Selective reviewer skip / PROP-7 (R2§2 §2.i)

A reviewer is skip-eligible next round ONLY when it produced nothing `severity ≥ MEDIUM` last
round. Skip overridden if new developer feedback touches that reviewer's scope. Skip is per-round,
not permanent.

### Decision 4 — Severity-driven stop + circuit-breaker / PROP-13B (R1 F16, R2§2)

Iterate while latest review (auto OR manual) yields `severity ≥ MEDIUM`. LOW-only → converged →
gate/approve. One non-convergence circuit-breaker: if MEDIUM+ persists across a defined number of
consecutive auto-review rounds → escalate to `requ-explore`. No complexity ceiling, no
version-count ceiling. (Developer: "Drop the complexity metric entirely.")

### Decision 5 — PROP-6 trim question.md by audience (R1 PROP-6)

`question.md` at Phase-3 gate carries ONLY decision-asks (RQ1/D1/D2/D3, A/B equivalents).
Orientation moves into the scribble. Fix-recap (the list of auto-review-resolved issues) is
deleted from `question.md` — it lives in `auto_review_brief.md` and per-reviewer files.
