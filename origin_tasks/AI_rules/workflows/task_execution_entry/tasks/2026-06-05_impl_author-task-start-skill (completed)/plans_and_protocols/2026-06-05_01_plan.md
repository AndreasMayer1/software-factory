## task-start SKILL.md content spec (from synthesis §1–§4)

```
name: task-start
description: Canonical single entry point for executing any already-created task.
             Resolves reference, gates pre-conditions, marks in_progress, delegates to claude-route.
tools: Read, Bash, Edit, Skill, AskUserQuestion
```

### Phase P0 — Resolve reference
- Input forms: goal.md path (use as-is), TASK-ID (grep), "next task"[+--type impl] (next_tasks.py selection loop), free-text (interactive AskUserQuestion)
- "next task" loop: show output, pick candidate, check in_progress/awaiting (same as claude-route Mode C today)
- No match → tell user / (automated) skip

### Phase P1 — Load & validate
- Confirm goal.md exists
- Run: `python3 scripts/tasks/validate_against_schema.py <goal> .claude/schemas/goal_metadata.yaml`
- Parse frontmatter: status, after, awaiting, opus_recommended
- Failure: HALT with schema error; do not proceed

### Phase P2 — Pre-condition gates
- P2a: status != completed (warn+confirm interactive / skip automated)
- P2b: awaiting empty — run `python3 scripts/tasks/is_awaiting_answer.py --task-id <TASK-ID>`; exit 1 → HALT "task is parked on developer answer" (interactive) / skip (automated)
- P2c: after: deps all completed — check each dep's status; failure → warn+confirm (interactive) / skip (automated)

### Phase P3 — Mark started
- If status pending/absent: set in_progress + started: <today> via Edit
- Automated mode: also write session_id + session_account (read from $CLAUDE_SESSION_ID, $CLAUDE_SESSION_ACCOUNT)
- Ordering: P3 BEFORE P4 (load-bearing for pending_feedback pre-condition)

### Phase P4 — Delegate
- Invoke claude-route skill with the validated goal.md PATH only
- claude-route now receives a ready, in_progress goal.md; it does type→skill match + opus-check + invoke
