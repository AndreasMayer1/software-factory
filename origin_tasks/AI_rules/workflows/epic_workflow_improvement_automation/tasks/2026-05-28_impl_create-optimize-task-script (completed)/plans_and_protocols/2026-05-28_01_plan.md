# Plan — `create_optimize_task.py` (IMPL-D / TASK-PROC-006-09)

## Objective

Build the single chokepoint through which claude-optimize creates improvement
tasks. Two non-removable invariants live here:

- **G-INV-1** — every produced `goal.md` contains `awaiting: ["user-unblock"]`,
  regardless of CLI flags / env vars / branches.
- **Write-Surface Deny-List (SEC-04)** — produced tasks whose `target_path`
  matches a deny-list entry are rejected at task-creation time with a non-zero
  exit code and a message naming the matched pattern.

## Deliverables

| Path | What |
|---|---|
| `scripts/optimize/create_optimize_task.py` | Producer CLI (tier C) |
| `scripts/tests/test_create_optimize_task.py` | Unit tests (tier C) |

## Inputs and Outputs

### Inputs (CLI)

The script accepts a candidate descriptor. Two equivalent entry points:

1. `--event <path>` — JSON event file written by a monitor (the production path).
2. Inline flags for direct invocation and tests:
   `--task-id`, `--target-path`, `--optimization-target`, `--optimization-dimension`,
   `--web-research / --no-web-research`, `--web-research-query`,
   `--web-research-reason`, `--scope`, `--objective`.

The event file (when used) provides `event_type`, `confidence`, `fingerprint`,
`payload`. Inline flags override fields derived from the event.

### Outputs

A single file `goal.md` written to the caller-supplied `--task-dir`, with:

```yaml
---
task_id: <id>
type: impl
parent_requirement: REQ-PROC-006
status: pending
created: <YYYY-MM-DD>
awaiting: ["user-unblock"]            # G-INV-1 (REQ-PROC-006 AC-04)
optimization_target: <one of SEC-02 values>
optimization_dimension: <one of SEC-02 values>
target_path: <relative path>
source_event:
  event_type: <type>
  fingerprint: <fp>
  confidence: <conf>
optimization_approach:
  web_research_recommended: true | false
  web_research_query: "<focused question>"   # iff recommended
  reason: "<one-line justification>"
---
# Goal: <derived title>
...
```

Stdout: the path to the written goal.md. Exit 0 on success.

### Deny-list rejection

Module-level constant `DENY_LIST` with the SEC-04 minimum (literal paths and
`scripts/quality/**` glob). On match: print
`deny-list: target_path '<x>' matches pattern '<y>'` to stderr and exit 2.
No file is written.

## Hard Constraints (must hold for every code path)

- **G-INV-1**: there is exactly one place in the script where `awaiting:` is
  emitted, and the value is a hard-coded literal `["user-unblock"]`. No `if`,
  no flag, no env var feeds into that line. A code comment on that line names
  G-INV-1 and AC-04.
- **Deny-list before write**: the deny-list check runs before any filesystem
  write. A failed check yields no goal.md.
- **No interactive prompts**: pure CLI, no `input()`, no stdin reads.
- **Tier C** header.

## Test plan

`scripts/tests/test_create_optimize_task.py`:

1. `test_emits_user_unblock_for_all_flag_combinations` — parametrized over
   {target × dimension × research-on/off} → every produced YAML parses with
   `awaiting == ["user-unblock"]`.
2. `test_deny_list_rejects_each_sec04_path` — parametrized over the 8 SEC-04
   entries; each invocation exits non-zero and names the matched pattern.
3. `test_deny_list_glob_matches_nested_path` — `scripts/quality/check_x.py`
   under the `scripts/quality/**` glob is rejected.
4. `test_normal_target_produces_valid_goal_md` — non-deny-listed target with
   minimal inputs produces a parseable YAML frontmatter and a body title.
5. `test_optimization_approach_block_present` — both branches
   (`web_research_recommended: true` carries `web_research_query`;
   `false` omits it).
6. `test_source_event_fields_populated_from_event_file` — feeding a JSON event
   file populates `source_event:` correctly.
