# Synthesis (Phase 4) — TASK-PROC-004-02

Convergent evaluation of the ideation set. Scoring is feasibility/impact/fit on 1–3.

## Central insight (from clustering)

The ideas cluster into **two mechanisms over one shared artifact**:

- **Mechanism A — Divergence** (idea *quality*): defeat structural premature convergence via prompt structure + frame fan-out (NOT temperature).
- **Mechanism B — Completeness** (answer *coverage*): defeat the per-request output-budget ceiling via a bounded gap-driven multi-run loop.
- **Shared artifact — the Ledger**: in Mechanism A it holds *idea/cluster candidates*; in Mechanism B it holds *open gaps (breadth/depth)*. It is the single source of truth, the termination meter, and the cache-saver (agents read the small ledger, not the whole prior synthesis). This unification (ideas I1/I2/I7/I15/I16/I25) is the load-bearing design decision.

Crucially, the gathering proved **most of this already exists in the factory** (I6/I15/I16): the orchestrator resume = continuation vehicle; `cycle_state.json` 5-cycle back-pressure = bounded loop with human escalation; `requ-verify-flow-coverage` = gap-extraction→synthesis; `pending_feedback` = the file-watch user gate. **The implementation is mostly composition, not invention.** This is the strongest guard against over-engineering (Tension T5, Seed 5).

## Decision 1 — Vehicle: **layered**, effort-gated (resolves KU1, T1, T5)

Reject "one vehicle." The right answer is a **three-layer stack**, each layer added only as effort rises:

| Layer | Artifact | When used | Why |
|---|---|---|---|
| **L0 — Protocol doc** | `doc/process/ideation_protocol.md` (+ ledger schema, prompt blocks) | always (read by opt-in skills) | I23/I28: no new always-loaded skill → honors token economy (REQ-PROC-059 b/e/h). Skills `Read` it just-in-time. The protocol is LAW; skills reference it. |
| **L1 — Inline multi-frame divergence** | a section the calling skill runs *in its own session* | Quick / Standard | C3: a skill doesn't isolate context, but for low-stakes work single-session multi-**frame CoT** (sequential personas, mode-separated prompts) is enough; avoids spawn cost. |
| **L2 — Isolated branch agents + reviewer agent** | `ideation-explorer` (generator) + a `*-reviewer` (gap/critic) agent | Deep, or any high-reversal-cost decision | ADHD evidence: real anti-anchoring needs **context-isolated branches**; only the Agent tool isolates (C3). The reviewer agent certifies gap-emptiness (I12), reusing the han-adversarial-validator precedent. |

**Why layered beats a single dedicated skill (I29) or single agent (I30):** the user's worry was right — a pure agent pays cold-start reload every iteration (T1). But the follow-up clarified the *completeness* constraint is output budget, not input context (I6), so **same-session continuation needs no reload** and L1 handles the common case for free. Isolation (L2) is reserved for where ADHD's evidence says it actually pays (Deep). Effort gates the layers — directly operationalizing the requirement's Quick/Standard/Deep.

Scores: L0 feas 3 / impact 3 / fit 3. L1 3/2/3. L2 2/3/3. **Adopt all three as a stack.**

Rejected: I31 direct-API temperature wrapper (feas 1 — blocked by C1/C5; **recorded as future unlock**, not built). I32 persistent server (feas 1, over-engineered). Pure I29/I30 single-vehicle (fit 2 — ignores effort calibration).

## Decision 2 — Divergence design (resolves KU through Mechanism A; C1)

Temperature is OUT (C1 + weak evidence). Divergence comes from **four prompt-level levers**, mandated in the ideation prompt block:

1. **CoT structure** (the #1 diversity lever, arXiv 2402.01727) — each divergence pass reasons step-by-step before listing ideas.
2. **Frame fan-out** — N frames from a curated **software-architecture frame library** (distributed-systems engineer, security auditor, data-locality optimizer, failure-mode analyst, $0-infra operator, biologist, regulator). L1 runs them sequentially in one session; L2 runs them as isolated branch agents (anti-anchoring "by construction").
3. **Strict generator/critic mode separation** (mechanical): the divergence prompt **forbids** evaluation/ranking/hedging; the synthesis/critic prompt **forbids** generation. One call doing both collapses divergence.
4. **Curated random stimulus** (I8) — a per-pass token from a wordlist file, for reproducible auditability.

REQ-PROC-004's seven techniques are **retained but re-cast as frames/operations *inside* this structure**, not as a linear checklist (web finding: sequential SCAMPER yields nearby UX tweaks; frames-in-isolated-branches surface novel *architecture*).

### Draft ideation prompt block (paste-ready for L0)
> **IDEATION MODE — GENERATOR ONLY.** You are diverging, not deciding. Rules: (1) Think step by step before listing ideas (chain-of-thought). (2) You will be given ONE frame — fully inhabit it; re-ask the problem as *"how would a {frame} solve this?"* and answer only from that frame. (3) Do NOT evaluate, rank, hedge, or filter — filtering happens later. No idea is too unusual, expensive, or speculative to include. (4) For each idea give: a one-line statement, the frame it came from, and a feasibility tag (a=now / b=hard / c=breakthrough). (5) Apply at least one inversion ("what would make this fail?" → invert) and one cross-domain analogy. Generate at minimum {min_ideas} ideas. Append each as a row to the ledger; never edit existing rows.

(For L1, run this block once per frame sequentially; for L2, spawn one agent per frame with disjoint context.)

## Decision 3 — The Ledger (resolves KU2; the shared artifact)

One file: `plans_and_protocols/[date]_NN_ledger.md` (or `.yaml`). Markdown table for human-readability + grep. Schema (merges Magentic task-ledger + Reviewer-adds-subquestions + factory's coverage_by idiom):

| field | values | purpose |
|---|---|---|
| `id` | L001… | stable ref |
| `parent_id` | id \| — | breadth tree / DAG of sub-questions |
| `item` | text | the sub-question (Mech B) or idea (Mech A) |
| `kind` | `idea` \| `gap` | which mechanism owns the row |
| `gap_type` | `breadth` \| `depth` \| — | breadth = sub-question never opened; depth = opened but shallow |
| `status` | `open`→`in_progress`→`answered`\|`partial`\|`dropped` | WIP/kanban (I1) |
| `frame` | frame name | detect mono-frame blind spots (I26) |
| `depth_score` | 0–3 | drives depth-gap detection (partial if < threshold) |
| `iter_opened` / `iter_closed` | int | convergence delta tracking |
| `evidence` | refs | citations / file links for answered items |

**Breadth vs depth handling differs**: a breadth gap is closed by *opening* it (a new divergence/research pass on that sub-question); a depth gap is closed by *deepening* an existing `partial` row above the `depth_score` threshold. The critic only ever **appends `gap` rows or flags `answered`→`partial`** — never rewrites settled content (I10, anti-oscillation).

## Decision 4 — The multi-run iteration loop (resolves KU2/KU3; the follow-up's core ask)

Each **iteration** = one model request, structured as:

1. **Gap-detection FIRST** (web finding: gap-detector runs first each cycle). The detector reads the ledger + analyze-phase scope map and computes `gaps = scope − answered` (I7, set-difference, not vibe). It appends breadth gaps (scope items with no row) and flags shallow rows as depth gaps. **Who runs it:** at L1 a self-pass with an explicit "what did I NOT cover?" critic prompt; at L2 a **separate reviewer-role agent** (self-assessment is biased — arXiv 2402.11436; external critic materially better).
2. **Advance**: the generator/synthesizer closes the highest-priority `open` rows it can fit *within this request's output budget* — explicitly leaving the rest `open` for the next iteration. This is the key move: the loop exists **because** one request can't emit everything (the follow-up's root cause), so each iteration deliberately consumes only what fits and hands the remainder forward via the ledger.
3. **Update + measure**: rewrite the ledger; record `open`-count delta.

### Continuation vehicle (resolves T1 second half)
- **Default = same session** (I6): because the constraint is *output* budget not *input* context, the next iteration continues in the same session — context is still present, it only needs the ledger to know what remains. Zero reload cost.
- **Cold restart (fresh agent per iteration)** only when (i) the session's *input* context is itself near limit, or (ii) anti-anchoring matters (Deep divergence). Then the carrier the new agent needs = **ledger + analyze-phase scope map + prior synthesis pointer** (not a full re-read) — the fresh-agent-per-batch pattern (CLAUDE.md §2). The carrier contents are the only thing that changes between the two vehicles.

### Terminal condition — "no gaps remain", operationalized (resolves KU3)
Fixpoint/thermostat framing (I2/I25). The loop halts when **ANY** holds:
- **`gaps_empty`**: no `open` rows AND no `partial` row below `depth_score` threshold (true "no gaps remain").
- **`max_iter`**: effort-bound cap reached (runaway backstop, I9).
- **`closure_rate < ε`**: `open`-count delta between iterations below threshold (diminishing returns — web evidence: 75% of gain in 2 rounds). Detects convergence on inherently-open questions.

On `max_iter` or `closure_rate` exit → **graceful degradation**: emit the synthesis WITH an `## Open Gaps` appendix listing remaining ledger rows (honesty requirement; AC). Never spin silently.

### Runaway backstop, effort-bound (resolves KU3)
| Effort | max_iter | min_ideas | frames | divergence vehicle | gap certifier |
|---|---|---|---|---|---|
| Quick | 1 | 10 | 2 | L1 inline | self-pass |
| Standard | 2 | 25 | 3 | L1 inline | self-pass |
| Deep | 3–4 | 50+ | 5 | L2 isolated branches | separate reviewer agent |

Mirrors REQ-PROC-004's effort table and the doc-lookup budget-band precedent. `closure_rate < ε` can stop *before* max_iter at any tier.

## Decision 5 — Unify the gates (resolves T2, KU4)

**One gate, the existing `pending_feedback` mechanism** (I11/I19, reusing the factory's file-watch pause verbatim). A single `question.md` write with a `mode:` field:
- `mode: ideation_review` — fired after the ideation/clustering pass (divergence→synthesis boundary). The file leads with the **most unusual idea + cluster map** (I14, observability-gap finding), invites the developer to append ideas, and accepts `APPROVED` / `ITERATE: …`.
- `mode: gap_escalation` — fired only if the completeness loop hits `max_iter`/`closure_rate` with material open gaps (mirrors the 5-cycle back-pressure escalation). Asks: raise the iteration budget, accept the partial, or split.

**Composition rule (resolves T2):** the *completeness* loop runs entirely **inside** a phase and does NOT open a gate per iteration — only the divergence→synthesis boundary (always) and a terminal escalation (only if capped-with-gaps) reach the human. So at most two human touch-points regardless of iteration count, and in automated mode both route through `pending_feedback` → orchestrator resume (C2 respected: no session self-scheduling).

**Interactive vs automated:** interactive = a live chat turn at the gate; automated = `pending_feedback` write + terminate + orchestrator resume. Same artifact, two resume drivers — already how the factory works.

## Decision 6 — Integration plan (resolves KU5; prioritized, minimal-first)

Per Seed 5 / T5, start minimal and prove value before spreading:

1. **First: `task-resolve`** (this very skill). It already has an "assess & plan" step (Step 2) and handles open-ended explore tasks — the exact population that complained. Insert an **opt-in L0/L1 ideation section** between gather and synthesis. Lowest risk, highest match. *This task itself is the proof case.*
2. **Second: requ-explore** — insert ideation between §1.6 (gather) and §2.0 (synthesis). High value (requirements benefit from divergence) but touches a load-bearing skill → do after task-resolve validates the protocol.
3. **Third: code-complex planning** — architecture decisions are exactly where ADHD's evidence is strongest; insert L2 branch divergence into Step 2 before the architecture-advisor converges. Highest divergence payoff, highest stakes → last.
4. **Later / opt-in: ux-create-flow, task-create explore template.**

Build order of vehicle layers: **L0 protocol doc first** (everything references it) → **L1 inline** (task-resolve) → **L2 agents** (`ideation-explorer` + reviewer, for code-complex/Deep).
