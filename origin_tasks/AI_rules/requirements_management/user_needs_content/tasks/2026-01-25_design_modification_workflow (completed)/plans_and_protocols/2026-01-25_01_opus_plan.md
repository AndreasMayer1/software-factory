**Created**: 2026-01-25
**Agent**: Opus (Strategic Planning)
**Task**: TASK-PROC-010-04

## Objective

Design a comprehensive workflow for modifying existing user needs artifacts (personas, scenarios, user flows) that:
1. Maintains traceability through version history and review tracking
2. Triggers appropriate re-approval workflows
3. Handles cascading impacts when higher-level artifacts change
4. Works for both human direct edits and AI-assisted modifications

---

## Analysis Summary

### Current State

**What Exists:**
- Three creation skills: `create-persona`, `create-scenario`, `create-user-flow`
- Review status system in YAML frontmatter: `draft | in_review | approved | deprecated`
- Review history tracking with date, from/to status, reviewer, and notes
- Version tracking via `version` field and `updated` date
- Evidence level markers throughout content (grounded/proto_persona/hypothesis)

**What's Missing:**
- No modify-* skills exist
- No documented workflow for modifications
- No impact analysis process (how changes cascade)
- No validation that modifications don't break cross-references
- No clear version incrementing strategy

**Key Insight from Requirements (REQ-PROC-010):**
Phase 4 explicitly lists these pending items:
- Create plan for how persona improvements propagate to scenarios/user flows
- Define process for cascading changes through all layers
- Determine task placement strategy for user needs modifications
- Address tooling requirements for change propagation

### The Modification Use Case (2026-01-21_smaller_additions)

The task needs to modify:
1. **Dr. Sarah persona** - Add pain points, mental models, enhance JTBD
2. **prepare_protocol_for_client scenario** - Update Act 2 showing time waste
3. **review_protocol_with_client scenario** - Update Act 1 showing data quality issues

These are **content enhancements**, not structural changes - adding/refining sections within existing files.

## Strategic Decision: Skill vs. Direct Edit

### Recommendation: **Hybrid Approach**

**Create ONE skill**: `modify-user-needs` (not three separate skills)

**Rationale:**
1. **Modifications are inherently simpler than creations** - no folder structure to create, no ID generation needed
2. **The complexity is in the workflow, not the action** - review status management, impact analysis, validation
3. **Direct editing is sometimes appropriate** - small typo fixes, quick updates
4. **A single skill can orchestrate all three artifact types** - unified workflow, consistent behavior

**When to use skill vs. direct edit:**

| Modification Type | Approach | Why |
|-------------------|----------|-----|
| Typo fixes, small wording changes | Direct edit | Overhead not justified |
| Adding new sections or significant content | `modify-user-needs` skill | Ensures review status, impact analysis |
| Major rewrites or structural changes | `modify-user-needs` skill | Critical for traceability |
| Changing evidence level markers | `modify-user-needs` skill | Affects data quality tracking |
| Updating cross-references | `modify-user-needs` skill | Needs validation |

## Workflow Design

### The `modify-user-needs` Skill Workflow

```
                    +------------------+
                    |  User requests   |
                    |   modification   |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 1. Identify      |
                    |    artifact(s)   |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 2. Read current  |
                    |    state         |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 3. Impact        |
                    |    Analysis      |
                    +--------+---------+
                             |
              +--------------+--------------+
              |                             |
     +--------v---------+         +---------v--------+
     | 4a. Downstream   |         | 4b. Upstream     |
     |     check        |         |     check        |
     | (what depends    |         | (what does this  |
     |  on this?)       |         |  depend on?)     |
     +--------+---------+         +---------+--------+
              |                             |
              +--------------+--------------+
                             |
                    +--------v---------+
                    | 5. Present plan  |
                    |    to user       |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 6. Apply         |
                    |    modifications |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 7. Update        |
                    |    metadata      |
                    +--------+---------+
                             |
                    +--------v---------+
                    | 8. Validate      |
                    |    & Report      |
                    +--------+---------+
```

### Step Details

#### Step 1: Identify Artifact(s)

Ask user for:
- Path to artifact(s) to modify, OR
- Artifact ID(s) (e.g., PERSONA-001, SCEN-001-02)

If ID provided, resolve to path:
```
PERSONA-001 → requirements_user_needs/personas/dr_sarah/persona.md
SCEN-001-02 → requirements_user_needs/personas/dr_sarah/scenarios/review_protocol_with_client/scenario.md
```

#### Step 2: Read Current State

Capture:
- Current YAML frontmatter (all fields)
- Current content sections
- Current `review_status` and `review_history`
- Current `version` and `updated` date
- Current evidence level markers count

#### Step 3: Impact Analysis

**For Personas:**
- List all scenarios under this persona folder
- Check if modifications affect:
  - Core needs (scenarios reference these)
  - Mental models (scenarios build on these)
  - Environmental constraints (flows reference these)
  - Anti-persona traits (scenarios/flows must not contradict)

**For Scenarios:**
- Check if modifications affect:
  - Success criteria (flows must meet these)
  - Context/triggers (flows must address these)
  - Three-act story (flows implement specific acts)
- List all user flows under this scenario

**For User Flows:**
- Check if modifications affect:
  - Steps (epics/features implement these)
  - Epic/feature references (bidirectional links)
  - Success metrics

#### Step 4a: Downstream Check (What Depends on This?)

```
Persona modified → Check scenarios for consistency
Scenario modified → Check user flows for consistency
User flow modified → Check epic/feature references
```

Output format:
```
Downstream Impact Assessment:
- SCEN-001-01 (Prepare Protocol): May need update to Act 2 (references "efficient professional" archetype)
- SCEN-001-02 (Review Protocol): No direct impact detected
- FLOW-001-01-01 (if exists): Check step 3 still aligns with modified scenario
```

#### Step 4b: Upstream Check (What Does This Depend On?)

```
User flow modified → Verify scenario still supports the goal
Scenario modified → Verify persona still supports the context
Persona modified → (no upstream dependencies)
```

#### Step 5: Present Plan to User

Before making changes, show:
```
=== MODIFICATION PLAN ===

Artifact: PERSONA-001 (Dr. Sarah)
Current status: approved
Will change to: in_review (requires re-approval)

Planned changes:
1. Add pain point: "Ineffiziente Redundanz" to Pain Points section
2. Add pain point: "Parking Lot Syndrome" to Pain Points section
3. Add mental model: "Vertrauen vor Kontrolle" to Mental Models section
4. Update JTBD: "Therapiepläne effizient erstellen und sicher übergeben"

Impact assessment:
- SCEN-001-01: Check if Act 2 needs update for time waste narrative
- SCEN-001-02: Check if Act 1 needs update for data quality issues

Version: 2.0 → 2.1

Proceed with modifications? (y/n)
```

#### Step 6: Apply Modifications

Use Edit tool to:
1. Update content sections as specified
2. Add appropriate evidence level markers
3. Include source reference if from a task: `🟢 [Data-Grounded: TASK-PROC-012-001]`

#### Step 7: Update Metadata

**YAML Frontmatter Updates:**

```yaml
# Increment version (semantic: major.minor for content changes)
version: "2.1"  # was "2.0"

# Update date
updated: 2026-01-25

# Reset review status (ALWAYS for significant modifications)
review_status: in_review  # was "approved"

# Append to review history
review_history:
  - date: 2026-01-25
    from: approved
    to: in_review
    reviewer: LLM
    notes: "Modified per TASK-PROC-012-001: Added pain points, mental model, updated JTBD"
```

**Version Incrementing Strategy:**

| Change Type | Version Change | Example |
|-------------|----------------|---------|
| Typo/grammar fixes | No change | 2.0 → 2.0 |
| Minor content additions | Patch (+0.1) | 2.0 → 2.1 |
| Section rewrites | Minor (+0.1) | 2.0 → 2.1 |
| Structural changes | Major (+1.0) | 2.0 → 3.0 |
| Evidence level changes | Minor (+0.1) | 2.0 → 2.1 |

#### Step 8: Validate & Report

**Validation Checks:**
1. YAML frontmatter valid and complete
2. Review status correctly set to `in_review`
3. Review history entry added
4. Version incremented appropriately
5. No broken cross-references introduced
6. Evidence markers present for new content

**Report Output:**
```
=== MODIFICATION COMPLETE ===

Modified: requirements_user_needs/personas/dr_sarah/persona.md
Version: 2.0 → 2.1
Status: approved → in_review

Changes applied:
- Added 2 pain points to "Pain Points with Current Paper-Based Approach"
- Added 1 mental model to "Mental Models & Expectations"
- Updated 1 JTBD in "Jobs to Be Done"

Review history updated: Entry added for 2026-01-25

Downstream artifacts to review:
- [ ] SCEN-001-01: Check Act 2 alignment
- [ ] SCEN-001-02: Check Act 1 alignment

Next steps:
1. User reviews modifications
2. Update downstream artifacts if needed
3. Change review_status to "approved" when ready
```

## Appendix: Direct Edit Guidelines

For cases where the skill is overkill:

### When Direct Editing is Appropriate

1. **Typo corrections**: Fix spelling, grammar without changing meaning
2. **Formatting fixes**: Adjust markdown formatting
3. **Link fixes**: Update broken relative paths

### Direct Edit Checklist

Even for direct edits, you SHOULD:
- [ ] Update `updated` date in frontmatter
- [ ] Keep `review_status` unchanged (typos don't need re-review)
- [ ] Do NOT add review_history entry for trivial changes

You MAY skip:
- Version increment (for trivial changes)
- Impact analysis (for isolated fixes)
