- Plan Template architektur: Ich finde, dass die "client copies" auch über die plan templates overview angezeigt werden können müssen. Use Case: Der THerapaut passt den Plan beim senden stark an. Nach der Therapiesizung denkt er: Oh das waren jetzt Änderungen die auch für andere Klienten Sinn machen, ich möchte mir den gesendeten Plan als neues Master Template anlegen. Der Einstiegspunkt übder den Klienten ist dafür nicht intuitiv, da man nicht erwartet, dass man den Plan vom Ordner des Klienten in die Template Übersicht kopieren kann. Die Client Copies sollten nicht direkt in der Template overview angezeigt werden, sondern jedes master template und jedes system template enthält einen Button (oder anderes passendes UI Element), um die Liste aller client copies anzuzeigen, die aus diesem template hervorgegangen sind. In dieser Liste kann der Therapeut die client copy öffnen, als master template duplizieren oder welche Aktionen noch Sinn machen.
- Für dr weber muss es möglich sein, dass er den plan überträgt und gleichzeitig den Instruction View für den Nutzer offen hält. Use Case: Dr Weber möchte, dass der Nutzer die App selbst erkundet. Dafür erklärt er den Plan nicht auf seinem Bildschirm und sendet dann, sondern er sendet erst und öffnet dann der Instruction View. Es darf also kein starrer Wizard sein. Stattdessen muss der Instruction View auch nach dem Senden geöffnet werden können. Vielleicht wird der Button um den Instruction View zu öffnen auch über den gesamten Prozess hinweg angezeigt und der Therapeut hat vollständige Kontrolle über das Timing. Das ist KEIN Grund warum der Instruction View kein Modal sein darf.
- Der Instruction View wird sehr viel Platz benötigen. Ich denke es macht Sinn, dass es ein Modal ist und alles andere verdeckt. Denn der View besteht aus der Ansicht für den Klienten und bei Bedarf daneben auch noch den Editor. Dieser Editor kann theoretisch die gleichen UI Widgets nutzen wie der Editor des Templates, aber es gibt einen Unterschied: Der Editor des Instruction Views zeigt die Kopie des Templates für den Klienten (client copy) an. Es ist also gut, wenn es nicht ganau das gleiche Formular ist das auch für das Template genutzt wird, damit der Theraput leichter versteht, dass es sich um eine Kopie handelt.
- Der Editor für den Instruction View muss manuell geöffnet werden (progressive disclousure). Gutes Pattern dafür: Ein edit button bei jeder Frage (gibt es dann natürlich nicht bei der Ansicht die später der Klient bei sich hat zum Daten eintragen). Dieser Edit Button öffnet den Editor an der entsprechenden Stelle. Es könnte auch sein, dass nur das betreffende Element zum Editieren angezeigt wird und sonst nichts, aber das sind UI Details die in dem User FLow zu weit führen.
