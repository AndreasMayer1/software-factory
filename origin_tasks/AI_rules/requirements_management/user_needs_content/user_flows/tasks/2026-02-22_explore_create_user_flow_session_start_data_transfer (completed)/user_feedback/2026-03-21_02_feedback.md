#### exception 4.1

We have to split that into the behaviour of the therapists app and the clients app. Therapists app first:
- for detection 15 seconds is fine. But we have to keep in mind that the timespan before the client even starts to try can very a lot: the therapist might open the transfer screen before the client managed to open his transfer screen - or he needs time to select which data he wants to send first. 
- That means that this troubleshooting prompt must not distract too much and must not hide too much of the screen, so that the client is not disturbed by it when he finally manages to show the qr code.

Clients app:
- The clients app does not know when the user started the transfer because the transfer is unidirectional. I only knows when the first qr codes are rendered. The clients might have to get up and walk to the therapists webcam. the therapist might need a while to open the receive screen. The user might already hold the phone into the webcam and the therapist app is actaully already receiving. We jsut don't know.
- But we should also show a troubleshootnig prompt regardless. Let's also use 15 seconds. The prompt must not hinder the user to show the qr code to the webcam. it must not hide the qr code in any way and must not lead to a feeling of rush, shame, guilt or similar for the user who maybe can't move fast enough. Also it must not imply that the users do anything wrong, because as stated, maybe the transfer is running, the app just doesn't know.


#### exception 4.2

- the app shows how much data is already transfered at any times. I don't think we need additionally a dialog after 30 seconds. the therapist can just close the transfer screen if he wants to abort.
- Side note: we use a fountain code and the data is encrypted. Therefore it won't be possible to save data partially. If the therapist closes the transfer screen, the already transfered data will be lost. in that case the therapist has to confirm that he really wants to leave the transfer screen. If the data transfer hasn't even started yet, the therapist can leave the transfer screen without dialog.

#### exception 4.3

- Correction: file transfer is NOT recommended default for remote sessions. Remote sessions are in almost every case a video call. the client can show his phone in his webcam and the therapist selects remote in his receving screen. Selecting remote on therapist side will open the screen capture feature. The therapists app will capture the whole screen. The therapist has to bring the video call image to the foreground with the window maximized. THe therapist app will scan the qr code from the screen capture of the video call.
- We should already specify how the file import works, because it is also part of this user flow. The receiving side will also have a button for file transfer. when this button is clicked it will open a file picker. but this is not the only way, because on all platforms files can be opened with <<program>>. In our case we use a special file ending and file meta data that is conencted to our app. The user can just open the file and the app will know what to do with it. In this case it is a transfer file that contains data. If the app is already opened in the transfer screen and the therapist already entered the name of the client, the app can just load the file into the clients profile. If the app is closed or not in the transfer screen, the app will open the transfer screen so that it can ask the therapist to which client the data belongs. Note: due to encryption the data can only be opened if the correct client is selected. Of course the therapist can also select "new client". But in that case he first has to do the pairing. Doing the pairing in this case is also solved already: The therapist can choose between qr code or passphrase. If he choose file transfer because the file is large, he can use qr for the pairing. If he choose file transfer because there is no video connection, he has to use the passphrase.
