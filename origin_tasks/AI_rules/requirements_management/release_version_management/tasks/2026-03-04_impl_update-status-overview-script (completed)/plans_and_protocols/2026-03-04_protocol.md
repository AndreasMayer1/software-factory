### Changes Made (all in `scripts/generate_status_overview.py`)

**Step 1 — Data Models:**
- `RequirementData`: Added `target_release: Optional[str] = None` field
- `TaskData`: Added `target_release: Optional[str] = None` field
- `_requirement_from_frontmatter()`: Parse `meta.get('target_release')`; parse per-item releases into `trackable_releases` dict; store in `trackable_items['releases']`
- `_task_from_frontmatter()`: Parse `meta.get('target_release')`

**Step 2 — `_parse_semver()`:**
- Added after `YAMLParser` class, before `StatusScanner`
- Tuple comparison on (major, minor, patch) — no packaging dependency
- WHY comment: avoids non-stdlib dependency

**Step 3 — `load_releases()`:**
- Added after `_parse_semver()`
- Reads `requirements_tasks/RELEASES.md` via `YAMLParser`
- Returns semver-sorted list; gracefully returns `[]` on missing file or parse failure
- WHY comment: convention-over-configuration for file path

**Step 4 — `--release VERSION` filter:**
- Added `--release` argument to argparser (in filtering options group)
- Applied filter in `main()` after `--category` filter; prints count of matching items

**Step 5 — `ReleaseSummaryReportGenerator`:**
- Standalone class (not subclassing `ReportGeneratorBase`)
- Shows per-release category breakdown table with open/done tasks and coverage %
- Two-set merge for known_versions + unknown_versions (WHY comment explaining graceful handling)
- Always shows "Unassigned" section at end
- Added `--release-summary` to mode_group; updated default-to-full guard

**Step 6 — `ReleaseConflictDetector`:**
- New utility class with `find_conflicts()` and `format_conflicts_section()`
- `_get_release_for_id()` checks both `_task_map` and `_req_map` (WHY comment: deps can point to either)
- `format_conflicts_section()` returns `[]` when no conflicts (WHY comment: no empty-section noise)
- WHY comment on class: enforces invariant release(X) >= release(Y) for X depends_on Y

**Step 7 — Existing generator integration:**
- `PriorityReportGenerator._generate_tasks_report()`: Added `Release` column
- `PriorityReportGenerator._generate_requirements_report()`: Added `Release` column
- `BlockersReportGenerator._generate_tasks_report()`: Appends conflict section at end (WHY comment)

**Step 8 — `FullReportGenerator` integration:**
- Added `releases: Optional[List[Dict[str, Any]]] = None` parameter to `__init__()`
- Added sections 5b (conflict warnings) and 5c (release summary) after coverage section
- Both sections are conditional (only shown when data exists)

**Step 9 — `main()` wiring:**
- Calls `load_releases(project_root)` after scanning; prints count or "disabled" message
- Applies `--release` filter after `--category` filter
- Dispatches `--release-summary` to `ReleaseSummaryReportGenerator`
- Passes `releases=releases` to `FullReportGenerator`
- Updated module docstring with new modes and options
