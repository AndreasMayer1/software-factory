# Synthesis: Python Code Quality Gaps vs Dart (TASK-PROC-051-05)

Date: 2026-05-28

## 1. Criteria Rubric — What "Bad Code" Means Beyond Lint/Type Gates

The existing five Python gates (G1–G5) enforce structural correctness: lint compliance, type safety, test pass, no hand-rolled YAML, print discipline. They do not constrain the **shape** of the code — how large functions grow, how complex their logic becomes, how many responsibilities they absorb. The following criteria capture the uncovered surface, measured objectively.

| # | Criterion | Metric | Scriptable? | Dart equivalent |
|---|---|---|---|---|
| C1 | Function body size | Statements per function | Yes — ruff `PLR0915` (default ≤ 50) | AC-02 SLOC ≤ 50 via `check_complexity.py` |
| C2 | Cyclomatic complexity | McCabe CC per function | Yes — ruff `C901` (default ≤ 10) | AC-02 CC ≤ 20 via `check_complexity.py` |
| C3 | Parameter count | Args per function (excl. self) | Yes — ruff `PLR0913` (default ≤ 5) | AC-02 params ≤ 4 via `check_complexity.py` |
| C4 | Control-flow nesting | Nested blocks per function | Yes — ruff `PLR1702` (default ≤ 5) | AC-02 nesting ≤ 5 via `check_complexity.py` |
| C5 | Branch count | Branches (if/elif/else) per function | Yes — ruff `PLR0912` (default ≤ 12) | No explicit gate (absorbed into CC) |
| C6 | Return-statement count | Return paths per function | Yes — ruff `PLR0911` (default ≤ 6) | No explicit gate |
| C7 | Magic values | Literal numbers/strings in comparisons | Yes — ruff `PLR2004` | No Dart gate (judgment only) |
| C8 | God-function pattern | Combination of C1+C2: function doing many unrelated things | Judgment-level | doc/ judgment + SLOC gate as backstop |
| C9 | Single responsibility | Module-level: one module, one responsibility | Judgment-level | Clean Architecture layer enforcement (G4) |
| C10 | Naming clarity | Meaningful names for variables, functions, parameters | Judgment-level | Judgment-level (no gate) |

**Key insight**: Criteria C1–C7 are scriptable and ruff already implements them natively. **No new dependency is required** — only a `pyproject.toml` configuration change adding `"PLR"` and/or `"C9"` to the ruff `select` list.

## 4. What Dart Already Protects Against

| Criterion | Dart protection | How |
|---|---|---|
| C1 Function size | **Yes — gated** | AC-02: SLOC ≤ 50, enforced by `check_complexity.py` (custom Dart AST analyzer) |
| C2 Cyclomatic complexity | **Yes — gated** | AC-02: CC ≤ 20, enforced by `check_complexity.py` |
| C3 Parameter count | **Yes — gated** | AC-02: params ≤ 4, enforced by `check_complexity.py` |
| C4 Nesting depth | **Yes — gated** | AC-02: nesting ≤ 5, enforced by `check_complexity.py` |
| C5 Branch count | Partially (via CC) | No explicit branch-count gate; CC covers most cases |
| C6 Return count | No | No explicit gate |
| C7 Magic values | No | Judgment-level only |
| C8 God-function | **Yes — gated** | SLOC ≤ 50 makes god-functions structurally impossible |
| C9 Single responsibility | **Yes — gated** | G4: Clean Architecture import rules (domain/data/presentation separation) |
| C10 Naming clarity | No | Judgment-level only |

**Summary**: Dart protects against C1–C4 and C8–C9 via gates. Python protects against none of these.

## 6. Decisions for User

### D1. Gate-set change: enable ruff PLR + C901 rules

**Proposal**: Add `"C9"`, `"PLR0912"`, `"PLR0913"`, `"PLR0915"`, `"PLR1702"`, `"PLR0911"` to ruff `select` in `pyproject.toml`, with per-file-ignores for `PLR2004` in test directories. Thresholds as proposed in §5.1.

**Trade-off**: Enabling at ruff defaults produces 336 violations on current code. Two strategies:
- (A) Enable with per-file baseline exceptions (suppress existing violations, gate only new code)
- (B) Enable with relaxed initial thresholds, tighten over time
- (C) Enable after cleanup (impl task refactors the worst offenders first)

**Recommendation**: Strategy (A) — enable immediately with baseline exceptions, then create a separate cleanup task. This prevents new violations from day one while acknowledging the existing debt.

**This is a gate-set change requiring user approval** (REQ-PROC-051 Key Decisions). This exploration documents the gap and recommendation; the actual `pyproject.toml` change is a follow-up impl task.

### D2. PLR2004 (magic values) in tests

**Proposal**: Exempt test files (`scripts/tests/*.py`, `scripts/automation/tests/*.py`) from PLR2004. Test assertions like `assert count == 3` are legitimate and readable; extracting `EXPECTED_COUNT = 3` adds noise without clarity.

**Alternative**: Enable everywhere and suppress individually (more noise, less value).

**Recommendation**: Exempt tests via per-file-ignores.

### D3. C901 threshold: 10 vs 15

**Rationale for 15 over the default 10**: Python orchestration scripts are inherently branchy — they handle multiple error paths, file-system states, and subprocess outcomes. McCabe 10 flags 75 functions; McCabe 15 flags a smaller set of genuine god-functions. Dart uses 20 but for Flutter widget build methods which have a different complexity profile.

**Alternative**: Start at 20 (match Dart) and tighten over time.

**Recommendation**: 15. It catches `process_answered_feedback` (CC 49), `write_health_summary` (CC 33), `write_report` (CC 26), `run_normal_session_step` (CC 24) — the genuine offenders — while allowing normal orchestration branching.

Create a follow-up impl task (TASK-PROC-051-06 or similar) that:

2. Sets thresholds:
   ```toml

   max-complexity = 15

   [tool.ruff.lint.pylint]
   max-args = 5
   max-branches = 12
   max-statements = 50
   max-nested-blocks = 5
   max-returns = 6
   ```
3. Adds per-file-ignores for test dirs: `"PLR2004"` in `scripts/tests/*.py` and `scripts/automation/tests/*.py`
4. Adds `# noqa: PLR0915` / `C901` / etc. with inline justification to all existing violations (baseline exception approach)
5. Updates `doc/python/README.md` gate table to list the new gates
6. Runs full gate suite to verify no regressions

A separate cleanup task (or series) addresses the worst god-functions over time.

## 8. What Was Not Known at Task Creation

- **The gap is fully closable with zero new dependencies.** Ruff 0.15.14 implements all pylint-refactoring rules (`PLR*`) and McCabe (`C901`) natively. The project's existing ruff config just needs `select` additions.
- **336 existing violations** at ruff defaults — the technical debt is quantifiable.
- **The pattern propagates** systematically: not just orchestrate.py but 5+ files have the same god-function/high-complexity signatures. The root cause is the existing guidelines' silence on function shape.
- **Magic values are the largest single category** (142 PLR2004 violations), but ~40% are in tests where they're often acceptable.
- **validate_meta.py has the highest density** of complexity violations (30% of functions exceed CC 20) despite being smaller than orchestrate.py — the problem is not confined to TIER A.
