# Plan: Wire G1, G3, AC-06 into Gate Runner

## Approach: inline

## Context
- Pre-commit hook calls `bash scripts/quality/check_quality_gates.sh` (settings.json PreToolUse hook)
- `check_quality_gates.sh` runs 12 custom scripts but NOT flutter analyze (G1), flutter test (G3), or AC-06
- `verify-quality` skill runs flutter analyze separately then calls check_quality_gates.sh — does not run flutter test
- `very_good_analysis` baseline in analysis_options.yaml already includes unawaited_futures, only_throw_errors, avoid_catches_without_on_clauses — so AC-06 is lint-covered by G1 but has no named gate in the runner

## Deliverables

1. **Modify `scripts/quality/check_quality_gates.sh`**
   - Add `--quick` flag parsing (skips flutter test for fast local checks)
   - Add G1 gate (flutter analyze) as inline section BEFORE the GATES loop
   - Add AC-06 to GATES array: `check_ac06_error_handling.py`
   - Add G3 gate (flutter test) as inline section AFTER the GATES loop (skipped with --quick)
   - Update header comment: gates count increases to 15

2. **Create `scripts/quality/check_ac06_error_handling.py`** (via claude-write-script)
   - Scan `lib/` for bare `catch` blocks (pattern: `catch (` not preceded by `on Type`)
   - Scan `lib/` for `throw` of string/int/bool/null literals
   - Accept `--exclude-paths` flag
   - Exit 0/1/2 convention

## Performance note
- flutter analyze: ~5-10s
- flutter test: ~55s
- --quick flag skips flutter test; pre-commit hook calls without --quick so it enforces G3
- verify-quality skill already runs flutter analyze before calling check_quality_gates.sh — double run is acceptable; no script changes needed for verify-quality

## Key decisions
- G1 and G3 are handled as inline gate sections (not in GATES array) because they're native flutter commands, not script files
- AC-06 regex check is belt-and-suspenders; primary enforcement is via G1 lint rules
- AC-06 checks bare catch in ALL of lib/ (not just persistence files) for simplicity; matches lint rule scope
