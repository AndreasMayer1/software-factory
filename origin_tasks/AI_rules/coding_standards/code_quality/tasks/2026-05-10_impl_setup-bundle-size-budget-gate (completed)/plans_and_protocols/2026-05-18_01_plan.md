# Plan — Bundle-size budget gate (REQ-PROC-046 AC-09 / G8)

## Deliverable

A single script `scripts/release/check_bundle_size.py` that:

1. Runs `flutter build apk --analyze-size --target-platform=android-arm64`
2. Runs `flutter build appbundle --analyze-size`
3. Stats the resulting `app-release.apk` and `app-release.aab`
4. Asserts APK per-ABI ≤ 30 MB and AAB ≤ 50 MB (configurable via CLI flags)
5. Archives the `*-code-size-analysis_*.json` files emitted by Flutter to
   `releases/<active-version>/size_analysis/<timestamp>/` so trends across
   releases are visible (AC-09 final sentence)
6. On budget violation, walks the size-analysis JSON depth-first and prints
   the top 10 contributors by bytes (the same data DevTools' "App Size" tool
   surfaces) so the LLM or developer can act on the failure

## Design decisions

- **Domain**: `scripts/release/` (release-pipeline pre-flight). Same neighbourhood
  as `check_release_preconditions.py`, whose pattern (sys.path bootstrap,
  `util.yaml_frontmatter` for reading RELEASES.md, Tier-C tag) this script
  mirrors.
- **Active-release detection**: read `requirements_tasks/RELEASES.md` via
  `util.yaml_frontmatter.read_frontmatter` and find the entry with
  `status: active`. CLI flag `--release-version` overrides if needed.
- **Skip-build flag**: `--skip-build` lets the script run against artifacts that
  Flutter already produced (useful when the build runs separately, e.g. on a
  CI Windows host via win-bridge, and only the threshold check needs to run in
  the devcontainer).
- **JSON path detection**: parse the path from `flutter build` stdout (Flutter
  prints `… can be found at: <path>`) rather than guessing the canonical path,
  which varies across Flutter versions (`build/`, `.dart_tool/flutter_build/`,
  `~/.flutter-devtools/`). Falls back to a `build/**` scan when `--skip-build`
  is set or stdout parsing fails.
- **Per-ABI APK**: building with `--target-platform=android-arm64` produces a
  single APK whose code section contains only arm64 — this IS the per-ABI APK
  the AC measures. `--split-per-abi` is not needed.
- **Print() discipline**: this is a CLI script with an `Output:` block in its
  module docstring, satisfying G5.
- **No Windows-bridge integration needed today**: Flutter + Android SDK are
  available in the devcontainer (`flutter doctor` reports Android 36 SDK with
  all licenses accepted), so the script runs locally. If a future host loses
  the toolchain, the script can be invoked via win-bridge once a
  `flutter_build_bundle_size` command_id is whitelisted in
  `win_bridge_watcher.ps1`.
